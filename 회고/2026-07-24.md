### [11:10] pull 충돌을 원격 main 기준으로 해결
- 맥락: `feat/interaction-hazard-coverage`에서 `origin/main`을 pull하던 중 `질문.md`와 설계 기록 문서에 충돌이 발생했다.
- 고민한 것: `질문.md`만 원격 버전으로 교체할지, 함께 발견된 설계 기록 충돌도 한쪽 버전으로 덮을지 검토했다.
- 트레이드오프: 모든 충돌에 원격 버전을 택하면 빠르게 끝나지만 설계 기록의 로컬 항목이 사라진다. 설계 기록을 수동 병합하면 내용을 보존하지만 충돌 구간의 의미를 확인해야 한다.
- 결론: `질문.md`는 요청대로 `origin/main` 버전을 선택했다. 설계 기록은 서로 다른 날짜의 추가 항목이라 양쪽을 시간순으로 보존했다.
- 어떻게 했는가: `git status`, `git ls-files -u`, UTF-8 `Get-Content`로 충돌을 확인했다. `git checkout --theirs -- 질문.md`와 수동 충돌 마커 제거 후 두 파일을 스테이징하고 merge commit `0878c9b`를 생성했다. `git pull origin main`을 재실행해 `Already up to date.`를 확인했다.
- 배운 점 / 다음에 볼 것: 사용자가 인지한 충돌 파일 외의 unmerged path도 먼저 확인해야 한다. 같은 위치에 추가된 기록끼리의 충돌은 한쪽 선택보다 의미 단위 병합이 정보 손실을 줄인다.
