## 사용자 피드백 누적

blog-draft 초안에 대한 세션 내 사용자 반응(raw)을 모은다. 위 시스템 설계 쟁점과 축이 다르므로 이 섹션에만 쌓는다.

- 캡처 주체: 인터랙티브 스킬 세션(파이프라인이 아님). 파이프라인은 JSON in/out이라 피드백을 받지 못한다.
- 일반화된 교훈은 `memory.md`로, 반복되어 굳어진 취향은 `soul.md`로 옮긴다.
- 같은 지적이 여러 번 반복되면 느린 루프(proposer)가 이 섹션을 context로 읽어 proposal에 반영한다.
- 긍정 피드백은 회귀 방지 신호로도 쓴다: proposal이 긍정 지점을 건드리면 경고 근거가 된다.

항목 형식:

```
- (YYYY-MM-DD, run_id, verdict=pos|neg) 사용자 반응 요약 → 도출한 교훈
```
