# Analyze Task Feedback

task 본문과 피드백을 근거로 논쟁의 구조를 복원한다. 피드백을 무조건 반박으로 취급하지 말고 질문, 반례, 범위 확장, 명확화 요구, 수정 제안 등 실제 역할을 판별한다.

## 1. 근거 수집

1. 대상 task의 요구사항, 제출 답안, 피드백을 모두 읽는다.
2. 각 피드백의 식별자, 지적 위치, 지적된 문장, 원문을 연결한다.
3. 지적된 문장만으로 주장을 확정하기 어려우면 앞뒤 문맥을 함께 읽는다.
4. task 밖의 자료가 필요하다는 피드백은 현재 자료로 답할 수 있는 범위와 추가 확인이 필요한 범위를 구분한다.
5. 원문에 없는 의도나 사실을 만들지 않는다. 해석은 `해석` 또는 `추정`이라고 표시한다.

## 2. 피드백 선별

다음 피드백은 분석에서 제외한다.

- 댓글 본문이 없는 이모지 또는 리액션
- 칭찬, 감사, 동의, 감상만 있고 새로운 근거·질문·조건·반례·수정 요구가 없는 댓글
- 작성자의 주장을 되풀이할 뿐 대응할 쟁점이 없는 댓글

다음 피드백은 포함한다.

- 칭찬이나 동의로 시작하더라도 뒤에 실질적인 질문이나 조건이 있는 댓글
- 기존 주장의 적용 범위, 숨은 전제, 예외, 실행 방법을 묻는 댓글
- 대안, 반례, 오류 지적, 구체화 요구를 제시하는 댓글

혼합된 댓글은 칭찬·동의 표현을 요약에서 덜어내고 실질적인 부분만 분석한다. 제외한 항목은 본문에 나열하지 말고 전체 개수와 제외 개수만 요약한다. 사용자가 제외 근거를 요구할 때만 식별자와 이유를 별도로 제시한다.

## 3. 주장과 피드백 복원

각 실질 피드백마다 다음을 작성한다.

### 원문 앵커

- 피드백 식별자와 위치, 지적된 task 문단 또는 섹션을 짧게 표시한다.
- 사용자가 원래 주장과 댓글을 바로 대조할 수 있는 최소 정보만 쓴다.

### 내가 주장한 내용

- 지적된 부분의 핵심 결론과 그 결론이 성립하는 전제 또는 범위를 함께 요약한다.
- 작성자가 명시하지 않은 강한 주장으로 확대하지 않는다.
- 같은 문단의 유보 조건이 있으면 생략하지 않는다.

### 피드백이 날아온 내용

- 칭찬 문구가 아니라 새로 제기된 질문, 반례, 조건, 수정 요구를 요약한다.
- 피드백이 원래 주장을 부정하는지, 범위를 넓히는지, 구체화를 요구하는지 구분해 표현한다.
- 원문이 질문이라면 단정적인 반박으로 바꾸지 않는다.

## 4. 답변·변론 후보 만들기

각 피드백에 서로 실질적으로 다른 후보를 2~3개 제시한다. 문구만 바꾼 같은 답을 여러 후보로 세지 않는다. 상황에 맞게 다음 관점을 조합한다.

- 피드백을 수용해 원래 주장의 범위나 조건을 보완한다.
- 원래 주장의 적용 범위를 명확히 하여 그 범위 안에서 방어한다.
- 양쪽의 핵심을 보존하는 새로운 구분이나 합성안을 제시한다.
- 지금 결정할 수 없다면 판단 기준과 추가로 확인할 증거를 제시한다.

각 후보는 실제 댓글에 바로 답할 수 있을 정도로 구체적으로 쓴다. 피드백을 다시 말하거나 원칙 이름만 나열하는 답은 후보로 세지 않는다.

현재 문맥에 더 적합한 후보를 제안할 수 있으면 `추천`이라고 표시하고 근거를 쓴다. 추천은 원문 요약이나 피드백 작성자의 의도가 아니라 분석자의 판단임을 분명히 한다.

## 5. 트레이드오프 연결

모든 후보 바로 아래에 해당 후보만의 트레이드오프를 붙인다. 최소한 다음을 드러낸다.

- 얻는 것: 설명력, 일관성, 변경 용이성, 검증 가능성 등
- 치르는 비용: 복잡성, 중복, 결합, 운영 부담, 추가 검증 등
- 적합 조건: 어떤 전제나 상황에서 이 후보가 유리한지

장점만 있는 선택지처럼 쓰지 않는다. 후보 사이의 차이가 판단 기준으로 이어지게 한다.

## 6. 출력 형식

```markdown
# <task 이름> 피드백 분석

전체 피드백 N건 중 실질 피드백 N건을 분석했다. 리액션·단순 동의 N건은 제외했다.

## <피드백 ID> · <쟁점 한 줄>

**원문 앵커**: <task 섹션 또는 위치> · <피드백 ID와 위치>

### 내가 주장한 내용
...

### 피드백이 날아온 내용
...

### 답변·변론 후보

1. **<후보의 입장>**: ...
   - **트레이드오프**: ...

2. **<후보의 입장>**: ...
   - **트레이드오프**: ...
```

필요하면 세 번째 후보를 추가한다. 문서에 저장하라는 요청이 없으면 대화에 출력하고, 저장 요청이나 반복 검토가 예상되면 대상 task 옆에 별도 분석 파일을 만든다. 원본 task와 피드백은 명시적 요청 없이 수정하지 않는다.

## 7. 완료 전 점검

- 모든 실질 피드백을 정확히 한 번씩 다뤘는가?
- 리액션과 단순 동의를 제외했는가?
- 혼합 댓글에서 실질적인 질문까지 버리지 않았는가?
- 각 항목에 원래 주장과 피드백을 다시 찾을 수 있는 앵커가 있는가?
- `내가 주장한 내용`이 원문의 유보 조건과 범위를 보존하는가?
- 피드백을 반박으로 과장하지 않았는가?
- 각 항목에 서로 다른 답변·변론 후보가 2~3개 있는가?
- 모든 후보에 후보별 비용과 적합 조건이 있는가?
- 추천을 원문 사실이나 피드백 작성자의 의도로 표현하지 않았는가?
- 사실, 원문 요약, 해석을 구분했는가?
