# Skeleton Agent Conventions

이 문서는 skeleton-agent가 계층형 생성 작업을 수행할 때 항상 따르는 범용 규칙이다. 특정 도메인, 아키텍처 스타일, 프레임워크, 파일 이름, 프로토콜, 저장 기술을 전제하지 않는다.

## Mission

정해진 산출물을 한 번에 만들지 않는다. 입력에 정의된 작업 단위 하나만 생성하고, 그 단위가 통과한 뒤 다음 단위로 넘어간다.

생성기는 설계를 다시 하지 않는다. 입력으로 받은 계약, 허용 경로, 작업 단위 지시, 이미 수용된 앞 작업 결과만 사용한다.

## Output Boundary

- 출력은 JSON 객체 하나다.
- JSON 최상위 필드는 `files`와 `notes`만 허용한다.
- `files[].path`는 설정된 source root 기준 상대 경로다.
- `files[].path`에 절대 경로, `..`, 테스트 경로, 허용 경로 밖의 경로를 넣지 않는다.
- 파일을 만들 때는 전체 본문을 출력한다.
- 생략 표시, diff 조각, 설명용 부분 코드를 쓰지 않는다.
- 현재 작업 단위의 허용 경로 밖 파일을 만들거나 수정하지 않는다.

## Frozen Contracts

- `CONTRACTS`에 들어온 파일은 읽기 전용이다.
- 계약의 공개 표면을 바꾸지 않는다.
- 공개 표면에는 타입 이름, 함수나 메서드 이름, 생성자 시그니처, 필드 이름, 오류 타입 이름, 외부 입출력 이름이 포함된다.
- 계약이 불편해도 바꾸지 않는다.
- 계약이 부족하거나 위험해 보이면 `notes`에 이유를 적는다.
- 계약에 없는 타입, 함수, 메서드, 필드를 임의로 만들지 않는다.
- 테스트 파일은 만들거나 수정하지 않는다.

## Unit Discipline

- 작업 단위 지시에 적힌 책임만 구현한다.
- 뒤 작업 단위가 만들 산출물을 미리 만들지 않는다.
- `ALREADY_BUILT`에 들어온 앞 작업 결과는 읽기만 한다.
- 앞 작업 결과가 불편해도 고치지 않는다.
- 막히면 우회 코드를 만들지 말고 `notes`에 막힌 지점을 적는다.

## Dependency Direction

- 의존 방향은 입력의 경계 규칙을 따른다.
- 더 안정적인 계약이 덜 안정적인 구현 세부에 의존하지 않게 한다.
- 구현 세부를 계약 표면에 노출하지 않는다.
- 서로 다른 작업 단위 사이를 우회해서 직접 연결하지 않는다.
- 조립 책임이 지정된 작업 단위가 아니면 구체 구현들을 임의로 묶지 않는다.

## Abstraction

- 새 추상화는 교체 축이나 경계가 입력에 명시되어 있을 때만 만든다.
- 단일 구현만 있고 경계도 요구되지 않으면 불필요한 인터페이스를 만들지 않는다.
- 계약을 구현할 때는 계약이 사용하는 언어를 따른다.
- 기술 세부 이름을 안정적인 계약 이름으로 승격하지 않는다.

## Mapping

- 서로 다른 경계의 모델을 분리하라는 지시가 있으면 변환은 경계 구현 내부에서 끝낸다.
- 한 경계의 내부 표현을 다른 경계의 공개 계약으로 노출하지 않는다.
- 저장된 상태나 외부 상태를 복원할 때, 상태 전이 API와 복원 API를 구분한다.
- 변환 과정에서 검증되지 않은 가정을 만들면 `notes`에 적는다.

## Error Handling

- 계약이 정한 오류 표현을 그대로 따른다.
- 구현 세부 오류를 안정적인 계약 밖으로 그대로 흘려보내지 않는다.
- 오류를 성공으로 바꾸거나 삼키지 않는다.
- 오류 매핑 규칙이 입력에 없으면 추측하지 말고 `notes`에 적는다.

## Comments

- 주석은 필요한 곳에만 쓴다.
- 주석은 무엇을 하는지보다 왜 그렇게 해야 하는지 설명한다.
- 통과를 위한 우회, 남은 위험, 검증되지 않는 가정은 코드가 아니라 `notes`에 적는다.

## Notes

- `notes`는 사람 검수자가 읽는 자료다.
- 자기 점수, 자기 판정, 통과 주장, 불필요한 요약을 쓰지 않는다.
- 계약이 불편한 지점, 게이트가 검증하지 못하는 가정, 막힌 지점, 선택한 trade-off만 쓴다.
- 외부 계약을 추측했다면 추측이라고 적는다.
