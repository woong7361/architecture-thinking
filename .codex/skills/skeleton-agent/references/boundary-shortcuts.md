# 경계 위반 카탈로그 (포트와 어댑터)

레이어를 생성할 때 지켜야 할 경계와, 실제로 자주 무너지는 지점을 모았다.
**특정 언어·프레임워크·도메인에 종속되지 않는 형태로 적는다.** 구체 이름이 필요한 규칙은 run 입력의
프로젝트 컨벤션이 담당한다.

> 출처: 톰 홈베르크, 『만들면서 배우는 클린 아키텍처』 — 의존성 역전, 경계 강제, 의식적 지름길 장.
> 프리먼·프라이스, 『테스트 주도 개발로 배우는 객체 지향 설계와 실천』 — walking skeleton, outside-in.
> 아래는 두 책에서 널리 알려진 개념을 이 파이프라인의 판정 관점으로 정리한 것이다.

---

## 1. 무엇을 만드는가 — walking skeleton

**walking skeleton은 껍데기가 아니라, 가장 얇지만 끝에서 끝까지 실제로 도는 한 줄기다.**
기능 수는 최소지만 각 조각은 진짜로 동작해야 한다. 비어 있는 인터페이스와 미구현 메서드를 넓게 깔아두는
것은 walking skeleton이 아니다. 판정 기준은 하나다 — **요청 하나가 바깥에서 들어가 끝까지 닿는가.**

바깥에서 안으로(outside-in) 만들 때도, 안쪽 계약이 먼저 고정되어 있어야 바깥이 그것을 향해 붙는다.
계약이 없으면 각 층이 자기 편한 계약을 지어내고, 그 지어낸 계약이 곧 경계 위반이 된다.

## 2. 의존 방향

- **의존은 항상 안쪽을 향한다.** 안쪽은 바깥을 참조하지 않는다.
- **소스 코드 의존 방향과 실행 순서는 다른 개념이다.** 런타임에 안쪽이 바깥 구현을 호출하더라도,
  소스 코드에서는 바깥이 안쪽의 추상에 의존한다. 이 뒤집기가 의존성 역전이다.
- 안쪽이 바깥을 향해 새는 순간, 바깥 기술을 바꿀 때 안쪽까지 함께 바뀐다.
  경계는 그 전파를 없애는 장치가 아니라 **범위를 줄이는 장치**다.

## 3. 포트가 지켜야 할 것

- 포트는 **안쪽이 소유하고 정의한다.** 바깥의 편의로 모양이 정해지면 그것은 포트가 아니다.
- 포트는 **업무 언어**로 쓴다. 전송 프로토콜·영속 기술·벤더 SDK의 타입이 포트 시그니처에 나타나면
  안쪽이 이미 바깥을 아는 것이다.
- 들어오는 포트는 안쪽이 **제공하는** 계약이고, 나가는 포트는 안쪽이 **요구하는** 계약이다.
  방향은 다르지만 소유자는 같다.

## 4. 자주 나오는 지름길 (전부 위반이다)

층을 만들다 막혔을 때 사람도 생성기도 이 지름길로 샌다. **막혔으면 지름길을 타지 말고 보고한다.**

| 지름길 | 무엇이 무너지나 |
|---|---|
| **들어오는 포트를 건너뛰고** 바깥이 안쪽 구현을 직접 호출 | 계약이 무의미해지고, 진입점이 여러 개로 갈라진다 |
| **유스케이스를 건너뛰고** 진입 어댑터가 나가는 포트를 직접 호출 | 업무 절차가 어댑터로 새고, 규칙이 두 곳에 생긴다 |
| 안쪽에 **프레임워크 애노테이션·타입**을 붙여 조립을 편하게 함 | 안쪽을 프레임워크 없이 실행·테스트할 수 없게 된다 |
| 도메인 모델을 **영속 모델·전송 모델로 겸용** | 저장 기술이나 프로토콜이 도메인 모양을 규정한다 |
| 계약이 불편해서 **포트 시그니처를 조용히 변경** | 그 포트를 함께 쓰는 다른 구현·다른 테스트가 소리 없이 깨진다 |
| 테스트가 빨간불이라 **테스트를 수정** | 심판이 부패한다. 그 시점부터 모든 초록불이 무의미하다 |
| 조립 지점이 아닌 곳에서 **구체 구현을 직접 생성** | 교체 축이 사라져 어댑터를 갈아끼울 수 없다 |

지름길이 항상 나쁜 것은 아니다. **다만 그것은 사람이 의식적으로 선택하고 기록할 일**이지,
생성기가 통과를 위해 몰래 택할 일이 아니다.

## 5. 경계는 규칙으로 강제한다

경계는 문서로만 두면 지켜지지 않는다. **의존 방향을 정적으로 검사해 위반을 빌드 실패로 만든다.**
사람이 리뷰로 잡는 방식은 재현되지 않고, 실패를 되먹일 수도 없다.

검사 도구를 쓸 때 두 가지를 주의한다.

- 검사 대상이 **하나도 없을 때** 규칙이 조용히 통과하거나 반대로 실패할 수 있다.
  전자는 공허한 초록불, 후자는 아직 만들지 않은 층을 위반으로 오인하는 거짓 빨간불이다.
- **항상 존재해야 하는 층**은 비어 있지 않음을 따로 단언한다.

## 6. 판정의 원칙

- 심판은 **관찰 가능한 동작**으로 판정한다. 내부 호출 순서나 구현 세부로 판정하지 않는다.
- 심판은 **아직 만들지 않은 것에 결합하지 않는다.** 결합하면 그 층이 없을 때 심판 자체가 빌드되지 않아
  판정 자체가 불가능해진다.
- 초록불이 증명하는 것은 **그 구성에서 동작한다**까지다. 대역이 남아 있는 만큼 증명 범위는 좁다.
