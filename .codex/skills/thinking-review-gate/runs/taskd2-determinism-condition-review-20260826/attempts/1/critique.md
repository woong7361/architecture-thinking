## 문제 지점

- [수정 범위] 초안은 표 앞과 표 뒤 문장만 고치는 방향으로 답했지만, 원문 발행본에는 이미 “게이트가 되려면 조건이 있다. 같은 코드에 같은 답을 내야 하고”라는 더 앞선 핵심 문장이 있다. 이 문장도 같은 오해를 만들 수 있으므로 함께 수정해야 한다.

- [결정성 claim] “AI가 만든 테스트나 명세를 사람이 승인해 고정한 뒤 기계가 실행할 때에만 같은 코드에 같은 판정이 나온다”는 방향은 맞지만, 조건이 아직 조금 넓다. 테스트 실행 환경, 현재 구현, fixture, 시간 의존성, 외부 I/O가 고정되어야 한다는 전제가 빠져 있다. 이 전제가 없으면 “기계 실행은 항상 결정적”이라는 식으로 다시 과장될 수 있다.

- [명세와 연결 코드] 표에서 “명세와 연결 코드를 고정한 뒤 기계가 실행한다”라고 쓰면, 본문이 말하는 “설계가 바뀌면 연결 코드는 다시 생성한다”는 흐름과 긴장이 생긴다. 같은 코드에 같은 판정을 말하는 순간에는 연결 코드까지 고정된 상태이고, 구현이 바뀐 뒤에는 같은 명세를 기준으로 새 연결 코드를 만든다는 식으로 범위를 분리해야 한다.

- [AI 직접 평가 근거] “지적 4건이 실제 실패 2건을 놓쳤다”는 원문 발행본의 관찰에 기대는 claim이다. 초안만 독립적으로 보면 해당 숫자가 어디서 나온 것인지 짧은 근거 연결이 없다. 최종 답변에서는 “원문에 이미 적힌 관찰 기준으로” 또는 “본문의 관찰을 유지한다면”처럼 근거 범위를 표시하는 편이 더 안전하다.

- [트레이드오프] 마지막 문장이 핵심 trade-off를 잘 잡았지만, “편의성을 포기”만 강조하면 AI 직접 평가의 장점이 과소평가될 수 있다. AI 직접 평가는 빠른 탐색과 리뷰 후보 발굴에는 쓸 수 있으나 최종 게이트로는 약하다는 식으로 역할을 나누면 더 정확하다.

## 확인 필요

- 원문에서 “같은 코드에 같은 답”이라는 표현이 표 외에 몇 군데 더 있는지 확인해야 한다. 최소한 문제 정의 섹션의 문장과 표 주변 결론은 같이 고쳐야 한다.

- AI 평가의 `Medium 3건`, `Low 1건`, 실제 실패 2건 누락이 같은 입력, 같은 모델, 같은 설정에서 반복된 결과인지 확인하면 좋다. 확인할 수 없다면 “이번 관찰에서는”으로 제한해 쓰는 것이 안전하다.

- 연결 코드까지 고정했을 때의 결정성을 말하는 것인지, 명세만 고정하고 연결 코드는 재생성하는 흐름까지 포함하는 것인지 문장 단위로 구분해야 한다.

## 수정 제안

- 표 앞 문장뿐 아니라 앞선 문제 정의 문장도 다음 취지로 바꾸는 것이 좋다: “게이트가 되려면 AI가 같은 답변을 해야 하는 것이 아니라, 승인된 기준과 실행 환경이 고정됐을 때 같은 구현에 같은 판정이 반복되어야 한다.”

- 표의 열 이름은 “같은 답을 얻는 조건”보다 “판정이 재현되는 조건”이 더 정확하다. “답”은 AI 응답처럼 읽히고, “판정”은 테스트 실행 결과와 더 잘 맞는다.

- 도메인 명세 행은 “명세와 현재 연결 코드를 고정한 동안에는 판정이 반복된다. 구현 경계가 바뀌면 명세는 유지하고 연결 코드는 다시 만든다”처럼 두 단계를 나누어 쓰는 편이 좋다.

- 결론 문장에는 “AI의 역할을 판정자에서 기준 후보 생성자와 연결 코드 작성자로 옮겼다”는 표현을 유지하되, “연결 코드는 별도 검증 대상”이라는 한계를 바로 붙여야 한다.

- AI 직접 평가는 완전히 버린 방식처럼 쓰기보다 “탐색에는 유용하지만 게이트로 쓰기에는 재현성이 약하다”로 정리하면 trade-off가 더 선명하다.

## 요약

초안은 사용자의 지적을 잘 반영해 “AI가 결정적인 것이 아니라 고정된 산출물과 실행기가 결정적이다”라는 핵심을 잡았다. 다만 원문 전체에서 같은 오해를 만들 수 있는 표현을 더 넓게 고쳐야 하고, 결정성이 성립하는 조건을 “고정된 기준, 고정된 연결 코드, 고정된 실행 환경, 같은 구현”으로 좁혀야 한다.
