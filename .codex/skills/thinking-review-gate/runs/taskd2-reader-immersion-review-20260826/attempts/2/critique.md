## 문제 지점

- [발행 범위] 블로그 본문은 첫 번째 `---` 이전이라고 문맥에 명시되어 있지만, 초안 파일 전체에는 과제 지시, 작업 메모, 자가 점검 메모가 함께 남아 있다. 실제 발행 또는 제출 과정에서 이 경계가 지켜지지 않으면 사용자가 문제 삼은 `task1-4.md`, `tdd-log.md` 같은 내부 기록 링크가 다시 독자 흐름을 끊을 수 있다.

- [근거 노출 방식] 본문에서 내부 파일 링크를 제거한 방향은 사용자 요청과 맞다. 다만 `Medium 3건과 Low 1건`, `6개 테스트`, `18개 중 2개 검출` 같은 수치가 본문 안에 바로 들어오면서, 독자가 “어떤 실험에서 나온 수치인가”를 추적할 최소 맥락은 일부 약하다. 링크를 다시 넣을 필요는 없지만, 수치가 나온 비교 조건이 처음 등장할 때 조금 더 명확해야 한다.

- [“AI가 만든 테스트로 AI가 만든 구현을 판정하는 안”] 초안은 이 안의 실패를 “직접 재현한 것은 아니다”라고 표시해 불확실성 경계는 잘 두었다. 그러나 바로 뒤에서 “명세가 코드 쪽으로 접힐 위험”을 근거로 채택하지 않았다고 하는데, 이 위험이 앞선 관찰에서 어떻게 이어지는지 연결이 조금 압축되어 있다. 독자가 보기에는 재현하지 않은 실패를 너무 큰 결정 근거로 삼는 것처럼 읽힐 수 있다.

- [할인 예시의 위치] 할인 예시는 테스트가 구현 모양을 고정한다는 주장을 보여주는 핵심 장면이다. 하지만 앞뒤 문맥이 환불 도메인으로 이어지기 때문에, 할인 예시가 같은 실험 흐름 안의 관찰인지, 별도의 예시인지 경계가 약하다. 독자 몰입 관점에서는 도메인이 갑자기 바뀐다는 느낌이 날 수 있다.

- [강한 문장] “검사받아야 할 쪽이 검사하는 쪽을 붙들고 있는 것이다”, “살아남은 것은 정책이다” 같은 문장은 글의 몰입도를 높인다. 다만 일부 문장은 근거 설명 직후에 충분히 작동하지만, 너무 자주 단정형으로 반복되면 기술 에세이보다 선언문처럼 읽힐 수 있다. 현재는 큰 문제는 아니지만 퇴고 시 밀도를 조정할 여지가 있다.

## 확인 필요

- 실제 발행본에 첫 번째 `---` 이전 본문만 사용할 것인지 확인해야 한다. 파일 전체를 그대로 발행하거나 복사하면 사용자 요청과 충돌한다.

- `Medium 3건·Low 1건`, `실제 실패 2건 누락`, `6개 테스트 통과`, `18개 중 2개 검출`이 기존 기록과 정확히 일치하는지 최종 발행 전 다시 확인해야 한다.

- 할인 예시가 실제 작업 기록의 사례인지, 설명을 위해 단순화한 예시인지 확인해야 한다. 실제 사례라면 본문 안에서 “다른 생성 테스트에서도”처럼 연결을 보강하는 편이 낫다.

## 수정 제안

- 발행본과 제출용 메모를 물리적으로 분리하거나, 최소한 발행 시 첫 번째 `---` 이전만 사용한다는 절차를 명확히 하라. 특히 작업 메모와 자가 점검 메모의 내부 링크는 블로그 본문에 섞이면 안 된다.

- 본문 수치는 유지하되, 링크 대신 한 문장짜리 실험 조건을 붙여라. 예를 들면 “같은 새 구현을 두 기준으로 판정했을 때”처럼 독자가 비교 대상을 바로 알 수 있게 만들면 된다.

- “AI가 만든 테스트로 AI가 만든 구현을 판정하는 안”은 직접 재현하지 않았다는 한계를 유지하되, 앞선 관찰과의 연결을 명시하라. 핵심은 “이미 생성 테스트가 호출 구조를 먼저 고정하는 현상을 봤기 때문에, 같은 산출물을 최종 판정 기준으로 삼는 것은 위험했다” 정도로 좁혀 쓰는 것이다.

- 할인 예시가 환불 실험과 다른 관찰이라면 전환 문장을 추가하라. 같은 실험 흐름이라면 같은 맥락임을 짧게 밝혀라. 독자가 도메인 전환 때문에 집중을 잃지 않게 하는 것이 목적이다.

- 내부 저장소 파일명, TDD 회차 번호, `.feature`, `setReserved`, v0/v1/v2 같은 내부 표기를 본문에서 제거하거나 풀어쓴 처리는 유지하라. 현재 방향은 사용자 요청에 부합한다.

## 요약

초안은 사용자가 지적한 내부 파일 링크와 작업 기록 표기를 본문에서 제거했고, 필요한 근거는 수치와 사례로 흡수했다. 다만 발행 범위가 지켜지지 않으면 내부 링크가 다시 노출될 수 있고, 일부 수치와 예시는 독자가 외부 파일 없이 이해할 수 있도록 비교 조건과 맥락을 조금 더 붙이는 편이 좋다.
