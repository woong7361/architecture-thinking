## 문제 지점

- [발행 범위] 초안 전체를 그대로 블로그에 옮기면 `Task D-2`, `수행 내용`, `제출물`, `작업 메모`, `자가 점검 메모`, `발행 링크`가 함께 노출된다. 검토 문맥에서는 `# AI의 테스트 게이트`부터 첫 번째 `---` 전까지만 블로그 본문이라고 했으므로, 발행 산출물과 제출용 과제 문서는 분리해야 한다.

- [내부 근거 링크 재노출] 블로그 본문에서는 `task1-4.md`, `tdd-log.md` 같은 내부 저장소 이동 문장을 제거했지만, 자가 점검 메모에는 다시 링크가 등장한다. 자가 점검 메모가 과제 제출용이면 허용 가능하지만, 블로그 발행본에 붙이면 사용자가 문제 삼은 방해 요소가 다시 생긴다.

- [“같은 새 구현” claim] 본문은 “AI 평가와 도메인 명세는 같은 새 구현을 판정했다”고 단정한다. 검토 문맥에는 `Medium 3건·Low 1건과 실제 실패 2건 누락`, `18개 중 2개 검출`은 확인되지만, 두 판정이 정확히 같은 구현을 대상으로 했다는 연결 근거는 초안 안에서 독자가 직접 확인하기 어렵다.

- [“생성기가 만든 테스트로 그 생성기의 산출물을 판정하는 구조”] 이 대안은 중요한 판단 지점이지만, 앞선 관찰과의 연결이 다소 추상적이다. 독자는 왜 이 구조가 실제로 위험한지 이해할 수는 있지만, 이 글의 실험에서 관찰된 사실인지 일반적 위험 추정인지 구분하기 어렵다.

- [독자 몰입 흐름] 글의 중반부는 내부 실험의 디테일을 잘 흡수했지만, “리네임”, “정책 판정 부분을 새 클래스로 떼어낼 때”, “명세에서도 그랬다”가 빠르게 이어진다. 처음 읽는 독자는 세 사례가 각각 무엇을 검증했는지 잠깐 놓칠 수 있다.

## 확인 필요

- 블로그에 실제로 발행할 범위가 `# AI의 테스트 게이트`부터 첫 번째 `---` 전까지인지 확인해야 한다. 그렇다면 초안 바깥의 과제 지시와 작업 메모는 critique 대상이 아니라 발행 제외 메타데이터로 남기면 된다.

- `AI 평가`와 `도메인 명세`가 정말 같은 새 구현을 대상으로 판정했는지 원 기록에서 확인해야 한다. 확인이 어렵다면 “같은 새 구현”이라는 표현은 “같은 실험 흐름에서” 또는 “새 구현을 두고”처럼 약하게 바꾸는 편이 안전하다.

- 자가 점검 메모가 블로그 본문과 함께 공개되는지, 과제 제출용 별도 메모인지 확인해야 한다. 공개 글에 포함된다면 내부 파일 링크 대신 본문처럼 수치와 사례를 직접 요약하는 방식이 더 맞다.

## 수정 제안

- 발행본에는 `# AI의 테스트 게이트` 본문만 남기고, 과제 지시, 작업 메모, 자가 점검 메모, 발행 링크 체크박스는 별도 제출 문서나 비공개 메모로 분리한다.

- “AI 평가와 도메인 명세는 같은 새 구현을 판정했다”는 문장은 근거가 확인되면 앞에서 짧게 연결 근거를 추가한다. 예를 들어 같은 구현을 두고 AI 리뷰와 동결 명세 실행을 각각 했다는 사실을 한 문장으로 넣는다. 근거 확인이 어렵다면 단정도를 낮춘다.

- “생성기가 만든 테스트로 그 생성기의 산출물을 판정하는 구조”는 관찰된 실패가 아니라 설계상 위험이라면 “이번 기록에서 직접 실패로 확인한 것은 아니지만” 같은 경계 표시를 붙인다. 또는 앞의 할인 테스트 사례와 연결해 “생성된 테스트가 구현 모양을 먼저 고정했던 기록 때문에”라고 근거를 명시한다.

- 세 사례가 이어지는 단락에는 각 사례의 역할을 한 문장씩 더 분명히 붙인다. 리네임 사례는 호출 방식의 취약성을, 판정 로직 분리 사례는 확인값의 생존을, 명세 연결 사례는 구현 연결 코드의 취약성을 보여준다고 정리하면 독자가 흐름을 덜 잃는다.

- 자가 점검 메모를 공개해야 한다면 내부 링크 문장을 그대로 두지 말고 “리네임 뒤 6개 테스트 통과”, “18개 시나리오 중 2개 실패”처럼 본문 안에서 이미 드러난 근거를 재사용한다.

## 요약

블로그 본문은 사용자가 문제 삼은 내부 파일 이동 문장을 대부분 제거했고, 핵심 근거를 수치와 전후 비교로 흡수해 독자 몰입을 높이는 방향으로 정리되어 있다. 다만 발행 범위가 섞이면 내부 작업 메모와 링크가 다시 방해 요소가 되며, “같은 새 구현”과 생성 테스트 판정 위험은 근거와 추정의 경계를 조금 더 분명히 해야 한다.
