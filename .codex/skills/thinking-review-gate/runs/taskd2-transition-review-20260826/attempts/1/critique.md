## 문제 지점

- [핵심 표현 교정] 초안은 “의도가 바뀌어갔다”가 실제 관찰과 어긋난다고 지적한 점은 좋지만, 대체 표현을 충분히 고정하지 않는다. 사용자가 바로 가져갈 핵심 문장은 “의도가 바뀐 것이 아니라, 의도를 담은 테스트 코드가 구현 호출 방식에 묶여 계속 바뀌었다”로 더 선명하게 제시하는 편이 좋다.

- [수정 범위] 초안은 전환 문단 예시를 주지만, 기존 발행본의 어느 절을 어떻게 바꾸라는지 조금 모호하다. 현재 문제 절인 `## 바뀐 것은 호출 방식이고, 남은 것은 정책이었다`의 제목과 첫 문단을 교체할지, 절 전체의 역할을 재정의할지 명시하면 실행 가능성이 올라간다.

- [근거 연결] “리팩터링 전후에도 확인한 값과 정책은 그대로였다”는 claim은 입력 본문에 근거가 있지만, 초안 안에서는 그 근거가 “6개 테스트가 그대로 통과했다”, “확인하는 값은 바뀌지 않았다”와 직접 연결되지 않는다. 사용자가 왜 이 표현이 더 정확한지 납득하려면 기존 글의 관찰 문장을 한 번 더 짚어주는 것이 좋다.

- [제목 제안] `리팩터링할수록 테스트 속 의도가 묻혔다`는 앞뒤 흐름에는 맞지만, “의도가 묻혔다”가 독자에게 “의도 자체가 사라졌다”로 읽힐 여지가 있다. 초안이 경계한 문제와 맞추려면 “리팩터링할수록 의도를 담은 코드가 흔들렸다”처럼 정책과 호출 코드의 분리를 더 직접적으로 드러내는 대안도 함께 제시하면 좋다.

## 확인 필요

- 사용자가 원하는 수정 수준이 전환 문장 보강인지, 해당 절 제목과 본문을 통째로 바꾸는 수준인지 확인하면 좋다.

- 실제 글에서 “환불 도메인 리팩터링” 사례를 유지할지, 할인 테스트 리팩터링 사례로 더 앞 단락과 밀착시킬지 저자 선택이 필요하다.

## 수정 제안

- 추천 흐름의 2번을 “그 설계를 리팩터링하자 테스트에 넣어둔 의도가 바뀐 것이 아니라, 의도를 확인하던 코드가 구현 변경을 따라 계속 바뀌었다”로 바꿔라.

- 예시 문단 첫 문장을 기존 절과 더 강하게 연결해라. 예: “앞에서 본 문제를 실제로 고쳐보려고 생성된 테스트와 구현을 함께 리팩터링했다.”

- “정책은 그대로였지만, 정책을 확인하는 코드가 구현에 묶여 있었다” 다음에 관찰 근거를 붙여라. 예: “이름과 호출은 바뀌었지만 전액 환불이어야 한다는 기대값과 6개 테스트의 판단은 그대로였다.”

- 제목은 단일 추천만 두기보다 2개 대안과 차이를 제시해라. 예: `리팩터링할수록 의도를 담은 코드가 흔들렸다`는 정확성이 높고, `리팩터링할수록 테스트 속 의도가 묻혔다`는 서사성이 강하다고 구분할 수 있다.

## 요약

초안은 사용자의 문제의식을 잘 받아서 “의도가 바뀐 것”이 아니라 “의도를 담은 코드가 구현에 묶여 흔들린 것”으로 교정한 점이 핵심 장점이다. 다만 실제 글에 적용할 교체 범위, 근거 연결, 제목 대안을 더 명확히 하면 사용자가 바로 수정에 옮기기 쉬운 critique가 된다.
