# 변경 결과 초안

## 결정과 대안

두 가지 반영안을 비교했다.

1. `AGENTS.md`에 "요약에는 예시를 넣는다" 한 줄만 추가하는 최소안
   - 장점: 규칙 변경이 작다.
   - 단점: 독자에게 필요한 맥락과 인과가 빠진 장식용 예시도 규칙을 충족할 수 있다.
2. 독자 관점, 인과 보존, 구체 예시를 하나의 일반 섹션으로 묶는 안
   - 장점: 요약, 리포트, 과제 답안 전반에서 읽기 쉬움의 판정 기준이 명확하다.
   - 단점: 규칙이 다섯 줄 늘어나고 작성자가 독자의 사전 지식을 별도로 고려해야 한다.

사용자의 "보는 사람 입장에서 쉽게"라는 목적을 직접 다루고 특정 과제에 고정되지 않는 2안을 선택했다.

## 실제 변경 1: `AGENTS.md`

루트 `AGENTS.md`의 `skill·공용 프롬프트 작성 규칙`과 `설명 요청 응답 형식` 사이, 현재 52행에 `요약·리포트 작성 원칙`을 추가했다.

- 앞선 논의를 보지 않은 독자를 기준으로 작성한다.
- 짧게 줄이는 것보다 맥락, 상황, 원인과 결과, 결론의 인과를 보존한다.
- 추상적 주장에는 코드, 시나리오, 전후 비교 중 적합한 예시를 최소 하나 포함한다.
- 전문 용어를 처음 등장할 때 풀어 쓴다.
- 표와 다이어그램은 관계를 더 분명하게 만들 때만 사용한다.

근거 anchor는 실제 프로젝트의 `AGENTS.md:52`이며, 기존의 도메인 중립적인 공용 규칙 작성 원칙과 충돌하지 않도록 특정 사례 명사를 넣지 않았다.

## 실제 변경 2: `taskC-1.md`

`답안 1: N-Tiered 한계 비평`의 Testability와 Flexibility 설명 직후, 현재 24행에 `예시: 주문 조회에서 JPA 엔티티를 전 계층이 공유한다면`을 추가했다.

예시는 다음 인과를 독자가 따라가게 한다.

```text
단위 테스트의 평범한 List
  -> 테스트 통과

실행 환경의 지연 로딩 컬렉션
  -> 영속성 컨텍스트 상태에 따라 접근 실패 또는 추가 조회 가능
  -> Mock만으로 차이를 재현하기 어려움
  -> JPA 통합 테스트 필요
```

변경 유연성은 `Order`를 API 응답까지 공유했을 때 `items` 매핑 변경이 Service 계산과 Controller 응답으로 전파되는 시나리오로 설명했다. JPA만의 문제로 오해하지 않도록 `OrderController -> OrderService -> JdbcOrderDao`가 `OrderRow`를 공유하는 JPA 없는 예시도 바로 뒤에 배치했다.

기술적 근거는 `taskC-1.md` 본문에서 [Hibernate ORM 6.6 User Guide](https://docs.hibernate.org/orm/6.6/userguide/html_single/)에 직접 연결했다. 이 문서는 엔티티의 관리·분리 상태, 지연 로딩, 영속성 컨텍스트의 동작을 설명한다. 기존 참고 절의 Jakarta Persistence 명세와 Microsoft N-tier 문서도 유지했다.

## 검증 결과

- PowerShell `Get-Content -Encoding utf8`로 두 파일을 다시 읽어 한글과 삽입 위치를 확인했다.
- `rg -n '^```'`로 코드 블록의 시작과 종료가 짝을 이루는 것을 확인했다.
- `git diff --check -- AGENTS.md task3/assignments/taskC-1.md`에서 공백 오류가 출력되지 않았다.
- `task3`는 현재 Git에서 미추적 디렉터리라 `git diff --stat`에는 나오지 않는다. 실제 저장 여부와 내용은 UTF-8 재읽기 결과로 확인했다.

## 최종 응답 초안

요청한 두 변경을 완료했다.

- `AGENTS.md:52`에 요약·리포트 작성 원칙을 추가했다. 사전 맥락이 없는 독자를 기준으로 맥락, 사례, 인과, 결론을 보존하고 추상적 주장에는 구체 예시를 최소 하나 포함하도록 했다.
- `task3/assignments/taskC-1.md:24`에 JPA 엔티티 공유 예시를 추가했다. 단위 테스트와 실제 지연 로딩 동작의 차이, 매핑 변경의 전파를 설명하고, JPA가 없는 `JdbcOrderDao`와 `OrderRow` 예시로 N-Tier 자체의 문제도 대비했다.
- 두 파일을 UTF-8로 재확인했고 Markdown 코드 블록과 공백 오류를 점검했다.

검토 과정에서 첫 실행은 로컬 Codex CLI가 기본 `gpt-5.6-sol`을 지원하지 않아 중단됐다. 로컬 모델 캐시에 있고 현재 CLI가 실행할 수 있는 `gpt-5.4`를 명시해 재검토했다. 설치나 설정 변경은 하지 않았다.
