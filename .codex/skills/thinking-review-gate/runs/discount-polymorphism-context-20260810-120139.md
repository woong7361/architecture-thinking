# Project Context

현재 `DiscountPolicy`는 단일 구체 클래스이며 다형성이나 정책 순회가 필요하지 않다. 직전 답변은 비율, VIP, 쿠폰 할인이 모두 누적되고 정책 목록이 동적으로 조립될 수 있다는 별도의 가정에서 순회 예시를 제시했다.

판단해야 할 핵심은 다음과 같다.

1. 매 요청에서 정확히 하나의 할인 알고리즘을 선택하는 Strategy 상황인지.
2. 여러 할인을 항상 정해진 순서로 누적하는 고정 조합 상황인지.
3. 적용할 할인 집합과 순서가 런타임에 달라지는 규칙 파이프라인 상황인지.

다형성은 구체 타입별 분기를 없애는 동적 디스패치이고, 순회는 여러 객체를 실행하는 제어 흐름이다. 두 개념은 대체 관계가 아니지만, 복수 실행 요구가 없으면 순회는 불필요하다.
