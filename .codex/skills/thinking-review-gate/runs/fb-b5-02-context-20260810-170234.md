# Project Context

현재 `refactoring-criteria.md`는 Type B 추상화의 결정 조건을 `v = 기존 구체 변형 수 + 확정 예정 변형 수`로 정의하고 `v >= 2`면 GO, 아니면 DEFER로 판정한다. `change-resilience-test.md`와 과제 본문은 두 번째 할인 종류가 생길 때 `DiscountPolicy` 인터페이스를 도출한다고 설명한다.

FB-B5-02는 요구가 두 번째 종류로 명확해지기 전에 점진적으로 복잡해지는 실무 상황을 지적하며 조기 신호를 묻는다. 앞선 FB-B5-01 논의는 변형의 개수만으로는 외부 I/O, 입력 형태, 고정 조합과 동적 조합의 차이를 판정할 수 없다는 결론에 도달했다.

대응안은 준비 리팩토링과 다형성 추상화 도입을 분리해야 한다. 현재 변경 경로에서 관찰되는 스멜은 구체 클래스 내부 응집, 외부 포트 분리, 테스트 보강 같은 저비용 준비를 정당화할 수 있다. 사용되지 않는 인터페이스, Factory, 정책 목록은 실제 대체 구현이나 런타임 선택 요구가 없으면 YAGNI 위반 가능성이 있다.
