# Constraints

- 사용자의 지적을 방어하지 않고 실제 모순과 누락을 교정한다.
- 규모와 현장 조건은 독립 결정 기준이 아니라 D/P의 발생 가능성 또는 별도 아키텍처 문제를 알려주는 문맥으로 내린다.
- `Legacy Schema`, `여러 데이터 소스`, `여러 팀`, `읽기 비중`만으로 Domain/JPA Entity 분리를 확정하지 않는다.
- 분리 구조는 의존 방향, 객체 변환 위치, 읽기와 저장 흐름, Mapper 비용이 발생하는 위치를 보여준다.
- 분리 방식은 특정 도메인에 고정된 공용 규칙이 아니라 설명용 Ticket 예시로 분리한다.
- 공개 사례가 입증하는 범위를 과장하지 않는다.
- 검토 통과 후 과제 파일을 수정한다.
