## 문제 지점

- [MP4/영상 입력 범위] 초안은 "지원되는 MP4 파일 하나"와 "지원되지 않는 영상 컨테이너일 때만 오디오를 자동 추출"이라고 써서, 비디오가 포함된 MP4도 그대로 전사 API에 보낼 수 있다는 인상을 줄 수 있다. 입력 근거에는 `gpt-transcribe`가 audio input은 지원하지만 video modality는 지원하지 않는다고 되어 있으므로, MP4가 오디오 파일 컨테이너인지 영상 파일인지에 따라 처리 조건을 더 명확히 해야 한다.

- [최신 가격 표현] 비용 섹션에서 "현재 가격"이라고만 쓰고 확인 기준일을 본문에 직접 붙이지 않았다. 입력에는 2026-08-26 공식 문서 확인 기준이 있으므로, 가격과 Free tier 관련 문장은 해당 날짜 기준임을 명시해야 한다.

- [전사 가능성과 필러워드 분석 가능성의 분리] 초안은 전사 API 호출과 필러워드 집계를 하나의 권장 흐름으로 잘 제시하지만, "전사는 가능하다"와 "`음`, `어`, `그` 같은 필러워드를 분석 가능한 수준으로 보존한다"는 서로 다른 claim이다. 위험 섹션에서 보존 미보장을 언급하긴 하지만, 권장 흐름 초반에서도 MVP의 성공 조건이 필러워드 recall 검증이라는 점을 더 선명히 연결하면 사용자가 과신하지 않는다.

- [말하기 속도 지표 정의] "분당 발화량"과 "구간별 속도"를 계산한다고 했지만 한국어 발표에서 무엇을 속도 단위로 삼을지 분명하지 않다. 단어 수, 음절 수, 글자 수, 어절 수 중 어떤 기준을 쓸지에 따라 결과가 달라질 수 있으므로 초안에 지표 정의 또는 초기 기본값이 필요하다.

## 확인 필요

- 사용자가 실제로 줄 파일이 순수 음성 파일인지, 영상이 포함된 MP4인지 확인하면 입력 처리 설명을 더 정확히 고칠 수 있다.

- 사용자가 외부 API 업로드를 허용하는지, 아니면 로컬 처리 선호가 강한지 확인하면 추천안을 `gpt-transcribe` 우선 또는 로컬 SeloWhisper 우선으로 조정할 수 있다.

- 발표 피드백에서 말하기 속도를 어떤 단위로 보고 싶은지 확인이 필요하다. 확인 전에는 한국어 기준으로 어절 수 또는 음절 수 중 하나를 기본값으로 제안하고 한계를 표시하는 편이 낫다.

## 수정 제안

- MP4 관련 문장을 "오디오 파일로서 지원되는 MP4는 그대로 보낼 수 있지만, 영상 파일이면 오디오 트랙 추출이 필요할 수 있다"처럼 바꿔라. `gpt-transcribe`가 video modality를 지원하지 않는다는 근거와 모순되지 않게 정리해야 한다.

- 비용 문장에 "2026-08-26 공식 문서 확인 기준"을 붙여라. 가격과 Free tier 여부는 변할 수 있으므로 최신성 한계를 표시하는 것이 좋다.

- 추천 결론에 "전사 자동화 자체는 가능하지만, taskD-5의 핵심인 필러워드 피드백은 첫 샘플 calibration을 통과해야 채택"이라는 조건을 더 앞쪽에 배치하라.

- 권장 흐름의 분석 단계에 말하기 속도 단위를 추가하라. 예를 들어 "초기에는 한국어 어절 수/분과 구간별 어절 수/분으로 계산하고, 필요하면 음절 수/초를 보조 지표로 둔다"처럼 검증 가능한 기본값을 제시하면 된다.

## 요약

초안은 사용자의 핵심 질문에 잘 답하고, Codex/Claude의 역할을 전사 엔진이 아니라 orchestrator로 분리한 점이 적절하다. 다만 MP4와 영상 입력의 경계, 가격 기준일, 필러워드 보존 검증 조건, 말하기 속도 지표 정의를 더 명확히 해야 사용자가 구현 방향을 과신하지 않고 검증 가능한 결정을 할 수 있다.
