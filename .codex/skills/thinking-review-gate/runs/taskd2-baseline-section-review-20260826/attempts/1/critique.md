## 문제 지점

- [절의 역할] 초안은 이 절을 “무엇을 바꿨는가”로 전환하라는 방향은 잘 잡았지만, 기존 절에서 중요한 대안 분석 부분을 어떻게 처리할지 명시하지 않았다. 현재 원문에는 “단위 테스트를 생성해 명세로 쓰는 안”과 “AI가 만든 테스트로 AI가 만든 구현을 판정하는 안”을 버린 이유가 들어 있다. 이 부분은 Task D-2의 4-Step 중 “대안 분석과 의사결정” 근거이므로 삭제하거나 약화하면 안 된다.

- [원인 설명 제거] “원인 설명을 걷어낸다”는 제안은 방향상 맞지만, 원인을 완전히 빼면 앞 절과 이 절의 연결이 약해질 수 있다. 최소한 “정책과 호출 방식이 테스트 코드에 함께 들어간 것이 문제였다”는 한 문장 정도는 전환 문장으로 남겨야 한다.

- [수정 범위] 초안은 제목, 도입, 다이어그램, 구분 문단을 제안하지만 기존 섹션의 어느 문단을 대체하고 어느 문단을 유지할지까지는 구체화하지 않았다. 사용자는 “이쪽은 뭐가 바꿔야하지?”라고 물었으므로, 실제 수정 지점 단위로 답하면 더 바로 적용할 수 있다.

- [다이어그램] 제안한 다이어그램은 기존 가로 정렬보다 안전하지만, 마지막 두 줄의 “설계가 바뀌면 / 계속 남는 것”은 여전히 공백 정렬에 일부 기대고 있다. 블로그 렌더러에서 한글 폭이나 줄바꿈이 달라질 수 있다는 사용자의 문제 제기를 완전히 해결하려면, 마지막 비교도 정렬형 문장보다 줄 단위 목록으로 바꾸는 편이 더 안전하다.

- [명세와 연결 코드 구분] 초안은 “연결 코드와 단위 테스트”를 함께 다시 만든다고 말한다. 원문에서는 “명세를 실제 코드에 잇는 부분”과 “구현 호출 방식에 묶인 단위 테스트와 연결 코드”가 함께 언급되므로 크게 틀리지는 않다. 다만 독자가 “명세 자체도 테스트 실행의 일부인데 무엇이 동결이고 무엇이 재생성인가”를 헷갈릴 수 있어, 동결 대상과 재생성 대상을 더 선명하게 나누는 표현이 필요하다.

## 확인 필요

- 현재 섹션의 두 대안 폐기 문단을 그대로 유지할지, 더 짧게 압축할지 확인이 필요하다. 이 문단은 4-Step 과제 요구사항과 직접 연결되므로 완전 삭제는 위험하다.

- 발행 플랫폼이 코드 블록의 한글 폭을 어떻게 렌더링하는지 확인하면 좋다. 확인이 어렵다면 공백 정렬을 전혀 쓰지 않는 세로형 다이어그램으로 고정하는 것이 안전하다.

- “연결 코드와 단위 테스트”라는 표현이 실제 작업물 구조와 맞는지 확인해야 한다. 실제로는 Gherkin feature, step definition, 단위 테스트가 구분되어 있을 가능성이 있으므로, 글에서는 “명세”, “명세를 코드에 잇는 연결 코드”, “필요 시 생성되는 테스트 코드”처럼 역할 중심으로 쓰는 편이 더 정확하다.

## 수정 제안

- 답변에 “기존 섹션 처리안”을 추가하라. 예를 들어 기존 첫 문단은 한 문장으로 압축하고, 기존 다이어그램은 세로 흐름으로 교체하며, 명세와 생성 코드 구분 문단은 유지하되 앞쪽으로 올리고, 두 대안 폐기 문단은 압축 유지한다고 제안하면 된다.

- 제목 추천은 유지해도 된다. `AI가 따라갈 기준선을 명세로 남겼다`는 앞 절의 결론을 받아 실제 행동으로 전환하는 제목이라 근거가 있다.

- 다이어그램은 공백 정렬이 없는 형태로 다시 제안하라. “설계가 바뀌면”과 “계속 남는 것”도 별도 줄로 분리해 렌더링 의존성을 줄이는 것이 좋다.

- “원인 설명을 걷어낸다”는 표현은 “앞 절에서 이미 설명한 원인은 한 문장만 남기고, 이 절에서는 바꾼 절차를 중심으로 쓴다”로 조정하라.

- 두 대안 폐기 문단은 이 절의 뒤쪽에 유지하되, 앞 절과 중복되는 증거 설명은 줄이고 “왜 버렸는가”만 남기라고 제안하라. 그래야 절의 역할이 실행 방식 설명과 의사결정 근거를 함께 담당한다.

## 요약

초안의 핵심 방향은 타당하다. 이 절은 “명세가 왜 필요한가”를 반복하기보다 “기준선을 명세로 남기기 위해 절차를 어떻게 바꿨는가”를 보여줘야 한다. 다만 기존 섹션의 대안 분석 문단을 어떻게 살릴지, 다이어그램을 공백 정렬 없이 완전히 안전하게 바꿀지, 동결 대상과 재생성 대상을 더 명확히 구분할지 보완이 필요하다.
