## 문제 지점

- [근거 앵커의 구체성] 초안은 각 피드백에 `본문 L117` 같은 원문 앵커를 달고 있지만, 구현·테스트 근거는 본문 안에서 파일 경로까지 다시 연결하지 않는다. `Holding.take()`의 스냅샷 한계, 인수테스트가 검증하지 않는 범위, 마이크로서비스 논의의 전제처럼 중요한 claim은 사용자가 바로 따라갈 수 있도록 `Holding.java`, `RegisteredMembers.java`, `ticket_reservation.feature` 등 확인된 파일 경로를 짧게 붙이는 편이 더 검증 가능하다.

- [근거보다 넓은 claim] FB-B7-03의 “장애 격리”는 checked context에 직접 근거가 없다. 입력에는 인수테스트가 내부 책임 배치, 다음 변경 비용, 동시성을 검증하지 않는다고 되어 있으므로, 장애 격리까지 포함하려면 추정 또는 일반화로 표시하거나 제거해야 한다.

- [인과 표현의 약한 경계] 초안 앞부분에서는 “형용사냐 숫자냐가 결과를 갈랐다”는 인과를 가설로 낮추지만, 종합 판단에서는 “구체적인 책임 규칙과 추상화 게이트가 결과의 변동과 과설계를 줄인 사례”라고 다시 비교적 강하게 쓴다. checked context는 입력 조건이 여러 면에서 달라 단일 원인을 확정하기 어렵다고 하므로, “줄인 사례”보다 “줄어든 결과가 관찰된 사례” 또는 “줄일 가능성을 보인 사례”처럼 낮추는 것이 일관된다.

- [추천의 판단 주체] 각 피드백 후보에 “추천”이 붙어 있지만, 왜 그 후보가 분석자의 추천인지 일부 항목은 충분히 드러나지 않는다. 성공 기준에 “추천은 분석자의 판단임을 표시한다”가 있으므로, 추천 후보마다 “분석자 판단으로는 현재 원문을 가장 덜 과장하면서 피드백에 답하기 때문” 같은 짧은 이유를 붙이면 더 명확하다.

- [FB-B7-04의 실행 절차 확장] “본선 코드”, “격리된 스파이크”, “후보 토너먼트”는 좋은 대응안이지만 원문 실험에서 직접 확인된 사실은 아니다. 설계 운영 제안임을 표시하면 사실 claim과 처방 claim이 더 잘 분리된다.

## 확인 필요

- 실제 최종 산출물이 “피드백 대응 후보 정리”인지, 아니면 “댓글로 바로 붙일 답변 문안”까지 요구하는지 확인하면 문체를 더 맞출 수 있다. 현재 초안은 분석 보고서와 댓글 후보의 중간 형태다.

- `taskB-7.md`의 실제 줄 번호가 현재 작업 디렉터리 기준으로 유지되는지 확인할 필요가 있다. 줄 번호가 변했다면 앵커는 파일 경로와 피드백 ID 중심으로 바꾸는 편이 안전하다.

- FB-B7-01을 “본문 없는 리액션”으로 제외한 판단은 input에 근거가 있지만, 최종 답변에서 제외 기준을 한 문장만 더 명시하면 누락으로 오해될 가능성이 줄어든다.

## 수정 제안

- 주요 근거가 필요한 문장에 확인된 파일 경로를 최소한으로 보강한다. 예를 들어 FB-B7-02에는 `task2/task7-history/code/variance/with-rule-r3/Holding.java`, FB-B7-03에는 `task2/task7-history/harness/net/resources/features/ticket_reservation.feature`, FB-B7-07에는 코드 줄 수와 파일 수가 대리 지표라는 한계를 연결한다.

- FB-B7-03의 “장애 격리”는 삭제하거나 “운영 진단 같은 테스트 밖 비용” 정도로 낮춰 쓴다. checked context에 없는 구체 항목을 새 사실처럼 추가하지 않는 것이 좋다.

- 종합 판단의 마지막 문장은 인과를 낮춰 수정한다. 예: “작은 Java 예매 예제에서 구체적인 책임 규칙과 추상화 게이트를 준 조건에서 결과 변동과 과설계가 줄어든 듯한 결과를 관찰했다. 다만 입력 조건이 여러 면에서 달라 원인은 후속 실험으로 분리해야 한다.”

- 추천 후보에는 추천 이유를 한 문장씩 붙인다. 이미 트레이드오프가 있으므로 길게 늘릴 필요는 없고, “현재 원문의 과장을 가장 적게 만들면서 피드백의 질문에 직접 답하기 때문에 추천한다” 수준이면 충분하다.

- 사실, 해석, 처방을 더 명확히 나눈다. 특히 FB-B7-04, FB-B7-06은 원문 실험 결과라기보다 후속 운영 전략이므로 “이 피드백에 대한 대응 전략으로는” 같은 표현을 앞에 두면 좋다.

## 요약

초안은 6개 실질 피드백을 모두 한 번씩 다루고, 후보와 트레이드오프도 충분히 제시한다. 다만 일부 일반화가 checked context보다 넓고, 파일 단위 근거 앵커가 부족하다. 인과 표현을 조금 낮추고 근거 경로를 보강하면 사용자가 검증 가능한 답변으로 더 안정적이다.
