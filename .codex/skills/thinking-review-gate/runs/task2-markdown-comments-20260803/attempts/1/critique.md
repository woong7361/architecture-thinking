## 문제 지점

- [작업 완료 상태] 사용자 요청은 "다 수정해줘"인데 초안은 `다음 변경을 동일하게 적용한다`, `수정 후 ... 확인한다`처럼 계획형으로 서술되어 있다. 실제 수정이 끝났는지, 아직 제안 단계인지 구분되지 않는다.
- [근거 앵커 부족] `<!-- notion-feedback:begin -->` 표식을 제거해도 된다는 판단, 프로젝트 내 참조처가 없다는 판단, `## 리뷰 피드백` 제목만으로 섹션 경계가 충분하다는 판단에 파일 경로나 검색 결과가 연결되어 있지 않다. 사용자가 초안만 보고는 확인 경로를 따라가기 어렵다.
- [검증 결과 누락] 4번 항목은 재검색과 diff 확인을 앞으로 할 일로만 적고 있다. HTML 주석, JSX, MDX 잔존 여부와 요청 범위 외 변경 없음은 핵심 검증인데 결과가 빠져 있다.
- [제약 반영 불완전] input의 제약인 `피드백 본문과 출처 정보를 유실하지 않는다`, `task2/assignments의 다른 본문은 변경하지 않는다`가 초안 본문에 명시적으로 반영되지 않았다. 메타데이터 형식 변경 설명만 있고 보존 여부와 변경 범위 제한이 답변 차원에서 확인되지 않는다.
- [대안 비교 부족] input에는 HTML 제거 대안으로 보이는 Markdown 텍스트 전환과 별도 파일 이동이 함께 있었는데, 초안은 현재안을 바로 선택한다. 마지막 문장에 trade-off는 있지만 다른 대안을 왜 버렸는지까지는 드러나지 않는다.

## 확인 필요

- `task2/assignments/taskB-0.md`부터 `taskB-7.md`까지 실제 수정이 적용된 상태인지, 아니면 아직 draft 수준인지 명확히 해야 한다.
- `<!--`, `-->`, JSX, MDX 재검색 결과가 대상 8개 파일 기준으로 모두 제거됐는지 확인 결과를 답변에 넣어야 한다.
- 메타데이터가 렌더링 결과에 보이게 되는 변화를 현재 사용자 요구 범위에서 허용 가능한 결과로 볼지, 아니면 별도 파일 분리가 더 맞는지 선택 근거를 더 분명히 해야 한다.

## 수정 제안

- 초안을 계획형에서 결과형으로 바꿔라. `...적용했다`, `...확인했다`처럼 실제 수행 여부를 먼저 밝히고 수정 파일 범위를 첫 문장에 고정해라.
- 각 핵심 claim에 evidence anchor를 붙여라. 예를 들면 `taskB-0.md`부터 `taskB-7.md`에 동일한 HTML 주석 구간이 있었고, 검색에서 `notion-feedback:begin` 참조처를 찾지 못했다는 식으로 파일 범위와 검색 사실을 함께 적어라.
- 검증 결과를 별도 문장으로 요약해라. `8개 파일에서 HTML 주석 표식을 제거했고 요청 범위 외 diff는 없음을 확인했다`처럼 사용자가 바로 판단할 수 있게 써라.
- 제약 충족을 명시해라. 피드백 본문과 출처 정보는 보존했고 변경은 리뷰 메타데이터 구간에 한정했다는 점을 답변 안에 넣어라.
- 선택 이유를 1-2문장 보강해라. Markdown에는 숨김 주석의 표준 문법이 없어서 `보이는 Markdown 메타데이터`와 `별도 파일 분리` 중 현재안을 택했다는 비교를 짧게 드러내면 된다.

## 요약

초안의 가장 큰 문제는 수정 결과 보고가 아니라 수정 계획처럼 읽힌다는 점이다. 완료 상태, 검증 결과, 제약 충족, 대안 비교를 결과형 문장과 근거 앵커로 보강해야 사용자가 바로 검증 가능한 답변이 된다.
