## 문제 지점

- [수동 스모크의 증명 범위] `declined-card` 요청에서 `402 + problem+json`을 확인한 것만으로는 `/charge` 호출과 `approved:false` 해석이 모두 검증됐다고 볼 수 없다. 잘못된 경로를 호출해 WireMock이 오류를 반환해도, 통신 실패를 미승인으로 처리하는 구현이라면 동일하게 402가 나올 수 있다.
- [과제 요구 범위] “C-6 과제의 최소 요구에는 현재 구성이 들어맞을 가능성이 높다”는 표현은 요구사항 1과 2를 나눠야 한다. HTTP부터 Testcontainers DB까지의 walking skeleton은 요구사항 1에 부합하지만, 요구사항 2는 각 Layer를 Cucumber 인수테스트로 판정하라고 한다. L1이 저장과 결제 어댑터를 함께 생성한다면 결제 코드를 실행하지 않는 게이트로 L1 전체를 판정해도 되는지는 별도 쟁점이다.
- [검증 항목의 근거 연결] 초안은 현재 Cucumber 테스트가 결제 실패의 402 변환과 미예약 상태를 검증한다고 설명하지만, 근거 목록에는 이를 직접 보여주는 feature 또는 step definition 파일이 없다. 테스트 구성 파일은 `PgChargeAdapter`가 우회된다는 사실만 직접 뒷받침한다.
- [계약 테스트라는 명칭] 로컬 WireMock 매핑만 기준으로 한 테스트는 애플리케이션이 그 매핑을 지키는지는 검증하지만 실제 PG 계약의 진실성은 보장하지 않는다. “어댑터 계약 테스트”라고 부르려면 로컬 fixture 기반 테스트인지, 제공자 계약으로부터 동기화된 테스트인지 구분해야 한다.
- [현재 상태와 제안 상태 혼합] 제안 문구의 “L1 판정에서는 별도의 어댑터 계약 테스트로 검증한다”는 현재 존재하지 않는 자동 테스트를 이미 운영 중인 것처럼 읽힐 수 있다. 이는 향후 수정안으로 명시해야 한다.
- [추천 테스트 범위] 승인과 거절 두 경우만으로는 입력에 명시된 전체 L1 계약을 덮지 못한다. 경로, HTTP 메서드, `paymentInfo`와 `amount` 요청 본문, `approved:true`, `approved:false`, 통신 실패 처리까지 포함해야 한다.
- [외부 PG 확인 방법] 공식 문서, 스키마, 샌드박스, 제공자 측 계약 테스트를 대안으로 제시한 방향은 적절하지만, 해당 PG가 실제로 어떤 검증 수단을 제공하는지는 확인되지 않았다. 모든 PG가 샌드박스나 제공자 측 계약 테스트를 제공한다고 단정하지 않아야 한다.

## 확인 필요

- 현재 저장소에 `PgChargeAdapter`를 실제 실행하는 자동 테스트가 별도로 존재하는가.
- Cucumber feature와 step definition이 결제 거절 시 402, `problem+json`, 미예약 상태를 각각 직접 단언하는가.
- `declined-card` 스모크 중 WireMock 요청 journal이나 verify 결과로 실제 `/charge` 요청과 본문을 확인했는가.
- 로컬 mock-pg 매핑의 근거가 실제 PG 공식 계약인지, 과제를 위해 사람이 정의한 내부 계약인지.
- 수정한 L1 지시가 현재 상태 설명인지, 향후 자동 게이트에 대한 제안인지.

## 수정 제안

- 설명의 중심을 세 범위로 분리한다. 현재 Cucumber 인수테스트는 `ChargePort` 이후의 업무 행위를 검증하고, 별도의 어댑터 통합 테스트는 결제 HTTP 프로토콜을 검증하며, 공식 문서나 샌드박스는 로컬에 적어 둔 계약이 실제 제공자 계약과 같은지 검증한다.
- C-6 요구사항 1의 walking skeleton 범위와 요구사항 2의 Layer별 판정 범위를 분리해서 평가한다. 전자는 충족 가능성이 높지만 후자는 L1의 판정 단위와 생성 범위가 어긋난 상태라고 설명한다.
- “수동 스모크가 이번 코드를 바로잡았다”는 표현을 축소한다. 코드 검토로 `/charge`와 `approved` 해석을 확인했고, 스모크는 애플리케이션에서 402로 이어지는 왕복을 확인했다고 구분한다.
- 스모크를 근거로 유지하려면 성공 카드가 200, 거절 카드가 402가 되는 두 경로를 함께 실행하고 WireMock의 수신 요청을 검증한다. 자동 게이트에는 같은 조건을 WireMock 기반 어댑터 통합 테스트로 옮긴다.
- 현재 자동 테스트가 없다면 수정 문구는 “별도의 어댑터 통합 테스트를 L1 게이트에 추가해야 한다”처럼 제안형으로 쓴다. 당장 추가하지 않는다면 “현재는 코드 검토와 docker compose 스모크로만 확인한다”고 현재 한계를 명시한다.
- 각 주요 claim 바로 뒤에 근거 파일을 연결한다. `E2eCucumberSpringConfiguration.java`와 `TestPaymentConfig.java`는 어댑터 우회를, Cucumber feature와 step definition은 업무 결과 단언을, `charge-declined.json`은 로컬 스텁 계약을 뒷받침하도록 배치한다.

## 요약

초안은 “외부 PG라서 못 하는 것이 아니라 현재 테스트 구성에서 어댑터를 우회한다”는 핵심을 정확히 짚었다. 가장 중요한 보완점은 402 스모크의 증명력을 과대평가하지 않는 것, walking skeleton 요구와 L1 전체 판정을 분리하는 것, 로컬 스텁 계약과 실제 PG 계약을 명확히 구분하는 것이다.
