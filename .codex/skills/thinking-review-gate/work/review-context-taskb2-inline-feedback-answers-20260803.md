# 검토 문맥

- 대상 파일: `task2/assignments/taskB-2.md`.
- 기존 형식: `taskB-0.md`와 `taskB-1.md`는 실질 댓글의 원문 코드 블록 바로 아래에 `**답변:**`과 1인칭 서술형 답변을 둔다.
- B-2 피드백은 FB-B2-01부터 04까지 댓글 4건이며 모두 새로운 질문이나 반례를 포함한다. 리액션만 있는 항목은 없다.
- FB-B2-01 확정 방향: application service가 outbound port를 호출하고 adapter가 외부 응답을 도메인 값으로 번역하며, domain이 그 값의 업무 의미를 판단한다.
- FB-B2-02 확정 방향: 조립 흐름은 inbound 경계부터 실제 service와 DB까지 묶고 외부만 대역으로 바꾸는 컴포넌트 인수테스트를 중심에 두며, 순수 규칙 단위 테스트와 소수의 외부 계약·E2E 테스트로 보완한다.
- FB-B2-03 확정 방향: 추상화는 두 번째 실제 사례, 반복 수정, 분기 복제, 독립 생명주기 같은 증거가 생길 때 도입한다. 다형성을 미리 만들지 않아도 변경 지점을 응집시키고 테스트로 보호한다.
- FB-B2-04 확정 방향: 같은 사전조건·사후조건·완료 상태·실패 의미를 지키면 `PaymentMethod`, 결제 차이가 예매 순서·상태·복구까지 전파되면 `ReservationFlow`로 경계를 올린다. transaction 경계는 객체 경계와 별도로 자원 구성을 보고 결정한다.
- 실제 DB 배치, transaction manager, 외부 결제 취소 계약은 제공되지 않았으므로 조건부 표현을 유지한다.
- 피드백 원문과 기존 답안은 수정하지 않고 각 코드 블록 아래에만 답변을 추가한다.
