# 글쓰기 규칙

글 전체와 그 안의 단위 사이의 관계를 정한 규칙이다. 이 저장소뿐 아니라 다른 컴퓨터와 다른 프로젝트에서도 쓰도록 여기 둔다. **이 파일이 원본이고, 각 컴퓨터의 전역 설정에 들어간 것은 복사본이다.** 규칙을 고칠 때는 이 파일을 고치고 복사본을 다시 맞춘다.

아래 `## 쓰기 전에 정한다`부터 파일 끝까지가 규칙 본문이고, 전역 설정에 들어가는 것과 글자 단위로 같다. 그래서 그 범위를 그대로 복사해 붙이면 된다.

## 다른 컴퓨터에서 쓰는 방법

둘 중 하나를 고른다.

**전역에 넣는다.** 규칙 본문을 `~/.claude/CLAUDE.md`와 `~/.codex/AGENTS.md`에 `# 글쓰기` 절로 붙인다. 두 파일은 각각 Claude Code와 Codex가 세션마다 읽는다. 한쪽만 넣으면 다른 도구가 규칙 없이 글을 쓴다. 세션마다 2,600자를 싣는 대가로 항상 적용된다.

**글 쓸 때만 읽힌다.** 전역에는 "글을 쓰기 전에 `docs/writing-rules.md`를 읽는다"는 한 줄만 두고 본문은 여기 남긴다. 매 세션 비용이 한 줄로 줄지만, 에이전트가 그 파일을 실제로 읽어야 적용된다.

## 복사본이 갈라졌는지 확인

전역에 넣는 쪽을 고르면 사본이 둘 생긴다. 저장소 루트에서 아래를 돌려 이 파일과 같은지 본다.

```bash
python - <<'EOF'
import re
from pathlib import Path
doc = Path('docs/writing-rules.md').read_text(encoding='utf-8')
src = re.search(r'(?ms)^## 쓰기 전에 정한다\s*$.*', doc).group(0).strip()
for f in [Path.home()/'.claude'/'CLAUDE.md', Path.home()/'.codex'/'AGENTS.md']:
    if not f.exists():
        print(f, '파일 없음'); continue
    m = re.search(r'(?ms)^# 글쓰기\s*$(.*?)(?=^# |\Z)', f.read_text(encoding='utf-8'))
    if not m:
        print(f, '글쓰기 절 없음')
    else:
        print(f, '동일' if m.group(1).strip() == src else '갈라짐')
EOF
```

## 쓰기 전에 정한다

독자는 이 주제를 처음 보는 사람으로 잡는다. 쓴 사람이 아는 것을 독자가 안다고 가정하지 않고, 대상과 상황을 파악하는 데 필요한 맥락은 본문에 포함한다.

장르를 하나 고르고 해당하는 줄을 먼저 적는다.

- 주장하는 글 — 논지를 한 문장으로 적고 아래 역할로 전개를 짠다. 논지를 쓸 수 없으면 아직 쓸 준비가 안 된 것이다.
- 찾아 쓰는 글 — 독자가 무엇을 들고 와서 무엇을 찾는지 적는다. 하나의 논지로 꿰지 않는다.
- 틀이 정해진 글 — 그 틀을 따르고, 틀의 각 자리 안에서 아래를 적용한다.

## 전개를 먼저 짠다

절마다 맡을 역할과 순서를 적은 다음 본문을 쓴다. 필요한 역할만 고르고, 한 절이 역할 둘을 맡으면 합친다.

| 역할 | 그 절이 하는 일 |
| --- | --- |
| 맥락 | 독자가 이미 받아들이는 것을 세운다 |
| 긴장 | 그 맥락에서 무엇이 어긋났는지 보인다 |
| 답 | 긴장이 만든 질문에 대한 논지 |
| 근거 | 답을 지지하는 사실과 사례 |
| 연결 | 그 근거가 왜 답을 지지하는지 |
| 반론 | 답을 약하게 만드는 것을 먼저 세우고 답한다 |
| 한정 | 답이 참인 범위와 깨지는 조건 |
| 마무리 | 독자가 읽고 무엇을 하면 되는지 |

맥락과 긴장은 답을 세우는 데 필요한 만큼만 쓰고 답을 앞에 둔다. 독자가 답을 거부할 이유가 있는 글에서만 공통 기반을 먼저 세우고 답을 뒤로 미룬다.

반론과 한정은 마무리 앞에 둔다. 마무리 뒤로 가면 결론이 도로 흔들린다.

소제목 목록을 먼저 확정한다. 소제목이 역할 순서를 잇지 못하면 본문을 쓰기 전에 고친다.

장르 규범이 전개를 따로 정해 두었으면 그것이 이긴다.

## 상위 단위가 약속한 것만 쓴다

소제목이 그 절에서 무엇을 말할지 약속하고, 문단과 문장이 그 약속을 지킨다. 어긴 단위는 다듬지 않고 지우거나, 약속을 지킬 수 있는 다른 글로 옮긴다.

| 단위 | 지킬 약속 | 어기는 예 |
| --- | --- | --- |
| 글 | 독자가 하려는 일 | 쓴 사람의 작업 과정과 조사 흔적 |
| 소제목 | 논지나 찾는 경로 | 논지를 진전시키지 않는 절 |
| 문단 | 소제목이 예고한 것 | 예고하지 않은 화제로 옮겨가는 문단 |
| 문장 | 그 문단의 핵심 | 사실이지만 핵심과 무관한 정보 |

## 문단

쓰기 전에 각 문단이 무엇을 설명해야 하는지 정한다. 한 문단에서는 하나의 핵심만 다룬다.

두괄식으로 쓴다. 첫 문장에는 그 문단이 답해야 하는 질문에 대한 핵심 답변을 둔다. 질문의 의미를 설명한다면 의도를, 판단을 설명한다면 결론을, 개념을 설명한다면 뜻을 먼저 밝힌다.

핵심 뒤에는 독자가 이해하는 데 필요한 이유와 근거를 연결한다. 추상적인 설명은 구체적인 상황이나 예시로 확인할 수 있게 한다. 모든 문단을 같은 순서나 항목 수에 억지로 맞추지 않는다.

## 문장

관계가 있는 문장은 어미로 이어 붙이고, 화제가 바뀌는 자리에서 끊는다. 근거와 대조를 별도 문장으로 떼면 독자가 그 관계를 스스로 복원해야 한다. 앞 문장과의 관계가 바뀌는 자리에는 전환을 드러내는 말을 둔다.

문장 길이를 섞는다. 비슷한 길이의 문장이 이어지면 어느 것도 강조되지 않는다. 길게 설명한 뒤 짧은 문장을 두면 그 문장이 결론으로 읽힌다.

익숙한 단어와 구체적인 동사를 쓴다. 전문 용어는 필요한 경우에만 쓰고 처음 등장할 때 뜻을 풀어 쓴다. 누가 무엇을 하고 무엇이 달라지는지 드러낸다. 말이 가리키는 동작이 실제로 일어나지 않으면 그 말을 쓰지 않는다. 비유는 독자가 이미 아는 것으로만 하고, 설명이 필요해지면 지운다.

긴 명사구를 만들어 문장 끝에서 닫지 않는다. 읽는 쪽이 끝까지 다 들고 가야 뜻이 서는 문장은 쪼갠다. 외국어를 구조째 옮기지 않고, 피동으로 옮긴 문장은 무엇이 무엇을 하는지 드러나게 되돌린다.

외국어 인용은 바로 앞이나 뒤에 그 뜻을 읽는 사람의 언어로 한 번 적는다. 인용이 정확한 것과 독자가 뜻을 받는 것은 다르다.

같은 뜻을 반복하는 문장, 불필요한 도입과 맺음말, 의미를 더하지 않는 수식어는 삭제한다. 다만 짧게 쓰기 위해 원인과 결과, 판단의 조건을 생략하지 않는다.

확인되지 않은 가정이나 제안은 사실처럼 단정하지 않는다. 문장을 줄이거나 순서를 바꿀 때도 원문의 조건과 확신 수준을 유지한다.

## 분량과 형식

고유명사, 수치, 인용은 논지를 세우는 데 필요한 만큼만 본문에 두고 나머지는 출처로 내린다. 같은 주장을 뒷받침하는 사례가 여럿이면 가장 강한 하나만 쓰고 나머지는 수로 센다.

이유와 흐름을 설명할 때는 문단을, 독립적인 항목을 나열할 때는 목록을 사용한다. 열거가 셋을 넘으면 순서를 바꿔 본다. 뜻이 같으면 논증이 아니라 목록이므로 목록으로 적거나 줄인다.

표와 강조는 관계나 핵심을 더 쉽게 파악하게 할 때만 사용한다. 강조가 문단마다 나타나면 강조로 기능하지 않는다. 핵심은 굵게 표시하는 대신 문단 첫 문장에 둔다.

## 점검

작성 후 다음을 점검하고 본문에 반영한다. 걸리면 문장을 다듬는 대신 구조를 고친다.

1. 소제목만 순서대로 읽어도 논지나 찾는 경로가 드러나는가?
2. 각 절이 전개에서 맡은 역할을 하고 있는가?
3. 문단의 첫 문장만 모아 읽어도 그 절의 논증이 되는가?
4. 처음 읽는 사람도 대상과 이유를 이해할 수 있는가? 설명 없이 지나간 용어가 있는가?
5. 비유와 추상 명사를 "무엇이 무엇을 한다"로 바꿀 수 있는가? 바꿀 수 있으면 바꾼다.
6. 지웠을 때 문단의 핵심이 약해지지 않는 문장이 남아 있는가?
7. 근거나 대조가 앞 문장과 끊겨 독립된 선언처럼 읽히지 않는가?

출처 표기와 확신도 표시는 6에서 지우지 않는다. 검토 과정은 별도 섹션으로 출력하지 않는다.
