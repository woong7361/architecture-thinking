# 쓰기 범위

## 무엇을 막는가

판정 대상이 아닌 파일이 움직여서, 게이트의 시야 밖에서 변경이 일어나는 것을 막는다.

## 원리

단계마다 쓰기 권한을 다르게 준다. 쓰는 단계는 작업 폴더 아래만 쓰고, 판정하는 단계는 쓰지 않는다.

작업 디렉터리를 작업 폴더로 두고 경계로 막는다. 프롬프트의 약속으로 막지 않는다.

승인이나 샌드박스를 우회하는 플래그는 쓰지 않는다. 모델이 셸을 쓸 일이 없으면 셸을 뺀다.

선언과 실물을 대조한다. 신고한 파일 목록과 실제로 바뀐 파일을 양방향으로 비교해, 신고에 없는 변경과 신고에만 있는 파일을 모두 위반으로 본다.

## 메커니즘

쓰기 권한이 넓으면 판정 대상 밖의 파일이 바뀌고, 그 변경은 게이트의 시야에 없으므로 판정되지 않은 표면이 된다. 판정 장치 자체가 그 시야 밖에 있으면 장치가 지워져도 그 사실을 판정이 알려주지 않는다. [[judge-integrity]]

경계로 막는 이유는 지시가 확률적으로 지켜지기 때문이다. 쓰기는 되돌리기 어려운 동작이라 한 번 새면 그 실행만 버리는 것으로 끝나지 않는다.

선언과 실물을 대조하는 이유는 신고가 주장이기 때문이다. 신고하지 않고 고친 것은 신고 목록만 보면 보이지 않고 실제 변경만 보면 의도를 알 수 없으므로, 둘을 맞춰야 조용히 놓인 파일이 드러난다. 주장과 판정을 분리하는 원칙이 파일 목록에도 적용된다.

## 예

쓰는 단계는 작업 폴더 쓰기를 받고 판정 단계는 읽기만 받는다. 셸은 양쪽에서 빼는데, 빌드는 하네스가 돌리고 경로는 입력이 주므로 모델이 셸을 쓸 일이 없다. 작업 폴더를 버전 관리 아래 두면 판본 스냅샷과 선언 대조를 같은 이력으로 해결한다.

## 경계

- 권한을 좁히는 것과 입력을 줄이는 것은 다르다. 판정 단계가 판정 대상을 읽지 못하면 못 읽은 것이 미충족으로 채점돼 전 축 최저점이 나온다. 읽기를 모델의 도구 성공에 맡기지 않고 필요한 것은 입력으로 같이 준다.
- 쓰기를 막는 것이 읽기를 막는 것은 아니다. 읽기 차단은 별도 장치다. [[information-blocking]]
- 권한 모델이 약한 실행기에서는 모드 하나로 끝나지 않는다. 금지 도구 목록을 따로 정한다.
- 작업 폴더를 반복마다 새로 만들지 않는다. 같은 폴더를 고치고 이력으로 판본을 남긴다.

## 검증

- [ ] 작업 폴더 밖의 변경이 탈락 사유가 되는가. 변경 목록은 신고가 아니라 실제 이력에서 뽑는다.
- [ ] 신고 목록과 실제 변경 목록을 양방향으로 대조하는가.
- [ ] 실행 인자에 우회 플래그가 없는가. 기본값도 본다.
- [ ] 단계별 권한 표가 실제 실행 인자와 일치하는가.
- [ ] 판정 단계가 판정 대상을 읽을 수 있는가. 전 축 최저점은 권한을 좁힌 부작용일 수 있다.
