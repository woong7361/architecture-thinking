# 기계 게이트와 판단 채점의 분리

## 무엇을 막는가

코드로 참과 거짓이 갈리는 것을 LLM에게 물어서, 통과 판정이 호출마다 흔들리는 것을 막는다.

## 원리

판정을 두 층으로 나눈다. 결정적으로 판정 가능한 것은 코드 게이트가 통과와 탈락으로 처리하고, 판단이 남는 것만 채점으로 보낸다. 게이트를 통과하지 못한 산출물은 채점하지 않는다.

최종 통과 여부는 채점자가 정하지 않는다. 점수는 재료이고 판정은 코드가 한다.

게이트는 의견이 아니라 사실을 본다. 구조, 존재, 수치, 일치, 실행 결과가 게이트의 재료다.

## 메커니즘

통과 기준은 재현돼야 하는데 LLM 판정은 같은 입력에 같은 답을 보장하지 않는다. 둘을 한 판정에 섞으면 전체가 약한 쪽의 성질을 가지므로, 결정적으로 판정할 수 있었던 부분까지 재현되지 않는다.

게이트를 채점 앞에 두면 두 가지가 더 생긴다. 이미 기계적으로 틀린 산출물에 채점 비용을 쓰지 않게 되고, 채점자가 형식 결함에 점수를 깎는 대신 내용만 보게 된다. 형식 결함이 점수로 번지면 그 점수는 내용에 대한 신호가 아니다.

사실로 내린 판정은 되먹일 수 있다는 점도 다르다. 실패한 실행의 메시지는 그대로 재시도 입력이 되지만, 채점자의 감상은 그렇게 쓰이지 못한다.

## 예

길이, 필수 필드, 금칙어, 식별자 일치, 선언한 파일 목록과 실제 변경 파일의 대조는 게이트가 보고, "근거가 설득력 있는가"는 채점이 본다. 점수 하한도 게이트가 본다. 점수는 채점자가 내지만 그 점수가 하한을 넘었는지는 코드가 판정하기 때문이다.

## 경계

- 게이트가 판정하지 못하는 것을 억지로 게이트로 만들지 않는다. 맞지 않는 규칙은 통과 트릭을 부른다.
- 게이트 항목이 산출물의 세부 표면에 걸리면 생성 쪽이 맞춰야 할 자리가 불필요하게 좁아진다. 계약 수준에서 잡는다.
- 게이트는 만든 뒤 반드시 양방향으로 리허설한다. [[judge-integrity]]
- 판단이 남는 축을 게이트로 못 옮긴다고 해서 흔들림을 받아들이라는 뜻은 아니다. [[rubric-ladder]]

## 검증

- [ ] 같은 산출물로 게이트를 반복 실행했을 때 결과가 동일한가. 하나라도 다르면 결정적이지 않다.
- [ ] 최종 통과 판정이 코드에서 나오는가. 채점 점수가 그대로 판정이 되면 판정이 흔들리는 값에 걸려 있다.
- [ ] 채점 근거가 필드 누락, 길이, 금칙어, 식별자 불일치 같은 형식 문제를 지적하는가. 그런 지적은 게이트로 올릴 후보다.
