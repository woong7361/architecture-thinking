# Task G-3: Retry + Jitter

(Grit's Why): 낙관적 락은 충돌 시 재시도를 전제로 합니다. 그런데 모두가 같은 순간에 재시도하면 충돌이 충돌을 부릅니다.

### 수행 내용

1. 낙관적 락 충돌 시 재시도 전략을 설계하세요. 고정 간격 재시도가 왜 동시 재시도 폭주(thundering herd)를 만드는지, 지수 백오프와 Jitter(무작위 분산)가 왜 그것을 완화하는지 설명합니다.
2. 무한 재시도를 방지하는 상한(최대 횟수)과 최종 실패 처리를 설계하세요. 재시도해도 안 되는 요청은 어떻게 사용자에게 응답할지(2-1의 에러 체계와 연결).
3. 본인 도메인에 Retry + Jitter를 적용하고, Jitter 유무에 따른 충돌율 차이를 관찰하세요.

### 제출물

- [ ] thundering herd 메커니즘 + 지수 백오프와 Jitter의 효과 + 재시도 상한과 최종 실패 처리. (최소 400자)
- [ ] Retry + Jitter 적용 코드(GitHub) + Jitter 유무 충돌율 비교. (최소 300자)
