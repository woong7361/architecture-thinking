# 이전 실험: 조회 후 실행 순서를 통제한 재현

이 디렉터리는 교체 전 테스트의 코드와 로그를 보관한다. 두 요청 모두 신청이 없다고 조회할 때까지 기다리게 했으므로, 이 결과를 내부 순서 제어 없는 요청의 발생 빈도로 해석할 수 없다.

사용자는 실제 기능에 동시 요청을 반복해 중복 발생 횟수를 관찰하는 방식을 원했다. 이에 ReadBarrier와 ObservationConfiguration을 Java 소스 경로 밖으로 옮겼으며 현재 테스트는 이 코드를 사용하지 않는다. 확장자가 `.java.txt`인 파일은 이전 구현을 확인하기 위한 기록이다.

현재 결과는 [100회 실험 로그](../concurrent-100.log)를 참조한다. 상위 디렉터리에 남아 있는 `kata-red.log`, `kata-red-junit.txt`, `compile.log`도 이전 실험의 기록이며 최신 결과에 합산하지 않는다.
