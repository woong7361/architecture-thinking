# 단계 2 — 리딩 하네스 run 기록

하네스는 [.codex/skills/source-evidence-agent](../../../../.codex/skills/source-evidence-agent)에 있고,
설계는 [v1-design.md](../../../../.codex/skills/source-evidence-agent/docs/v1-design.md)다.
이 폴더는 그 하네스가 낸 산출물과 사람이 읽을 리포트다.

run 상태는 `READY`다. 게이트 위반 0, 미판정 0, 하한 미달 0이다. **`READY`는 주장이 참이라는 뜻이 아니고
사람이 원문과 대조해 판정할 자료가 갖춰졌다는 뜻이다.**

## 파일

| 파일 | 무엇인가 |
| --- | --- |
| [verdicts.md](verdicts.md) | **먼저 읽는 판정 시트.** 주장마다 세 줄 |
| [REPORT.md](REPORT.md) | 시트에서 걸린 주장을 원문과 대조하는 자리. 세 절 |
| [claims.json](claims.json) | 주장 10개와 인용과 교환 항목 |
| [critique.json](critique.json) | 반대 조사자의 독립 판독과 제한 조항 |
| [eval.json](eval.json) | 주장별 축 칸과 채점 근거 |
| [verdict.json](verdict.json) | 통과 판정과 관찰 6건 |
| [sites.json](sites.json) | 추출기가 뽑은 동시성 API 지점 24개 |
| [ledger.jsonl](ledger.jsonl) | run 하나의 전체 이력. 재사용과 전송 실패까지 |

판정은 `verdicts.md`를 먼저 읽고 거기 적는다. 주장마다 세 줄이고, 그중 **주장과 원문의 차이** 한 줄이
판정의 재료다. 게이트가 인용의 실존을 이미 확인했으므로 남은 위험은 진짜 인용으로 원문보다 넓은 주장을
뒷받침하는 것이고, 그 차이가 거기 적혀 있다. 걸리는 주장만 `REPORT.md`의 그 묶음을 연다.

리포트는 하네스가 다시 쓴다. 사람이 쓴 판정을 거기 두면 다음 run에 덮인다.

**리포트는 그 run이 낸 마지막 제안만 다룬다.** 반복 중에 철회되거나 고쳐진 주장은 `ledger.jsonl`이
갖는다. 리포트에 이력을 실으면 지금 판정할 것과 지나간 것을 가려 읽어야 한다.

## 하네스가 한 일

| 자리 | 한 일 |
| --- | --- |
| 추출기 | 대상 코드에서 동시성 API 지점 24개를 열거. 커버리지 게이트의 분모다 |
| Gen | 코드와 답안에서 주장 10개를 뽑고 1차 출처에서 인용을 모았다 |
| 게이트 | 인용 실존, 출처 등급, 앵커 도달, 교환 좌표, 커버리지, 변경 신고 |
| Critique | 주장을 제한하는 조항을 인용으로 가져왔다 |
| Eval | 주장별로 네 축의 칸을 냈다. 합산하지 않는다 |
| Refine | 게이트 위반을 닫고 제한 조항을 주장 문장에 반영했다 |

주장 목록을 사람이 쓰지 않는다. 그래서 근거를 찾기 쉬운 주장만 뽑는 편향을 커버리지 게이트가 막는다.
지점 24개가 전부 덮였다.

## run 이력

| iteration | 자리 | 결과 |
| --- | --- | --- |
| 1 | gen | 주장 10개, 게이트 위반 0 |
| 1 | critique | Gen이 놓친 제한 조항 17건 |
| 1 | eval | 하한 미달 3건 |
| 1 | refine | 게이트 위반 0으로 유지 |
| 2 | critique | 놓친 조항 17 → 6건 |
| 2 | eval | 하한 미달 0건 |

전송 실패가 네 번 났고 모두 재시도로 넘겼다. 반복 상한은 품질 거절에만 썼다. 원장의 `stage_failure`와
`reuse` 기록이 그것이다.

## refine이 상한 안에서 어떻게 닫았나

제한 조항을 받아들이는 방법이 인용을 더하는 것이 아니었다. 인용은 주장당 3개가 상한이고 그 상한은 사람이
읽는 양을 묶어 둔 것이다. 그래서 **조항이 깎는 범위를 주장 문장에 넣었다.**

`claim-01`이 그 예다. "`REQUIRES_NEW`는 기존 트랜잭션을 보류한 뒤 새 트랜잭션을 시작한다"에
"보류는 트랜잭션 관리자가 보류를 구현한 경우에만 성립한다"가 붙었다. 뒷문장이 반대 조사자가 가져온
조항이고, 그것이 `grounding` 4점의 조건인 "원문이 단 조건이 주장 문장에 들어 있다"를 만든다.

## run을 돌려서야 나온 설계 수정 넷

책상에서 설계 문서를 읽을 때는 보이지 않았다. 자세한 이유는 v1-design.md §16에 있다.

| 자리 | 처음 | 지금 |
| --- | --- | --- |
| 지점 좌표 | 주장당 하나, 경로 문자열 | 배열, 지점 id |
| 출처 등급 | primary·measured 둘 | target을 더해 셋 |
| 좌표 형식 | `경로:12`만 | 범위와 스냅샷 경로까지 |
| `limiting_clause_missed` | violation | observation |

마지막 것이 가장 크다. 위반으로 두면 통과를 막는 쳇바퀴가 된다. Critique은 Gen 뒤에 돌면서 제한 조항을
찾는 일만 하므로 Gen이 안 가져온 조항을 거의 항상 찾아내고, 인용 상한 안에서 Gen이 그것을 미리 다
인용할 수는 없다. 조항을 안 가져온 것은 사실이지만 그것이 결함인지는 판단이라 `grounding`이 본다.

## 남은 한계

사실 주장의 근거를 사람이 아직 대조하지 않았다. 그것이 `verdicts.md`의 일이고, **기각이 한 건도 없으면
이 기록은 "AI가 맞다고 한다"를 한 겹 포장한 것이다.**

두 번째 iteration의 관찰 6건은 여전히 열려 있다. 반대 조사자가 찾았고 조사자가 가져오지 않은 조항이다.
`REPORT.md` 3절과 `verdicts.md`의 마지막 절에 그 자리가 있다.

출처 스냅샷은 저장소에 넣지 않았다. 명세와 수집 스크립트와
[해시 원장](../../../../.codex/skills/source-evidence-agent/sources/LEDGER.json)이 있으면 같은 스냅샷을
다시 만들고 같은 것인지 확인할 수 있다.
