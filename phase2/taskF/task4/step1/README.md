# 단계 1 — AI 구현 run

조건을 주지 않고 동시성 문제를 맡기고, [단계 0](../step0/README.md)의 재현 테스트로만 판정한다. 이 폴더에
가림 목록, 지시문, 자기 평가 양식, 그리고 run마다의 기록이 들어간다.

## 작업 공간을 저장소 밖에 둔 이유

이미 쓴 락 구현이 저장소에 있으므로, 같은 저장소에서 맡기면 가장 싼 경로가 그것을 복사하는 것이 된다.
조건을 주지 않았는데 답이 옆에 펼쳐져 있으면 조건을 준 것과 결과가 같아진다.

읽기 차단은 지시로 걸지 않고 경계로 건다. 지시는 확률적으로 지켜지고, 입력에 있는 정보를 무시하라는 지시는
그 정보를 한 번 더 읽게 만든다. 그래서 작업 공간을 저장소 밖에 복사하고 F-3 산출을 제거한 뒤 독립 git
저장소로 만들었다. 기준선 커밋이 `baseline: 동시 요청에서 중복이 생기는 상태`이고, 구현 diff는 그 커밋
기준으로 뜬다.

작업 공간 경로는 run 기록에 적는다. 세션 임시 경로라 run이 끝나면 diff와 로그만 이 폴더로 가져온다.

## 가린 것과 남긴 것

[blocked-paths.md](blocked-paths.md)에 목록과 각각의 이유가 있다. 남긴 것 중 힌트가 될 수 있는 것도 거기
적어 둔다. 가렸다고 선언하고 실제로 남아 있으면 기록이 그만큼 거짓이 된다.

## 산출의 순서가 고정이다

```
1  자기 평가      무엇을 막았는지, 어느 격리 수준을 전제했는지, 왜 통과할 것인지
2  구현           src/main 아래만
3  테스트 실행    mvn -Pkata-red -Dtest=AlertSubscriptionTest test
```

자기 평가를 먼저 받는 것이 이 단계의 전부다. 실패 로그를 본 뒤에 쓰게 하면 평가가 결과에 맞춰져서, 자기
평가와 테스트가 어긋난 자리가 사라진다. 양식은 [self-assessment-template.md](self-assessment-template.md)다.

## 판정

재현 테스트의 통과와 실패로만 판정한다. 구현이 맞는지 묻지 않는다.

통과 조건은 두 가지를 함께 본다. 중복이 0이고 **요청 오류도 0**이다. 단계 0에서 전 조건의 요청 오류가 0회
였으므로, 중복을 0으로 만들면서 오류를 만들면 그것은 통과가 아니다. 이 기준은 F-3에서 가장 강한 격리
수준이 중복 0건에 요청 오류 100회를 낸 관찰에서 나왔다.

테스트 경로가 변경 목록에 나타나면 그 run은 탈락이다. 판정 대상을 고쳐 초록불을 만든 것이기 때문이다.

이 검사는 둘을 함께 본다. `git status`로 추적 파일의 변경 목록을 보고, 해시는 줄 끝을 LF로 정규화한 뒤
동결값과 비교한다. 원본 해시만 쓰면 체크아웃의 줄 끝 변환으로 멀쩡한 run이 탈락한다. run 2에서 실제로
그렇게 어긋났다.

## 남길 것

run마다 폴더를 하나 만들고 넷을 넣는다.

| 파일 | 내용 |
| --- | --- |
| `self-assessment.md` | 테스트 실행 전에 받은 자기 평가 |
| `implementation.diff` | 기준선 커밋 대비 diff |
| `test.log` | 테스트 실행 원본 로그 |
| `verdict.md` | 통과·실패, 그리고 자기 평가와 어긋난 자리 |

어긋난 자리가 없으면 없다고 적는다. 없는 것을 만들어 적지 않는다. 다만 run을 여러 번 돌려 전부 어긋남이
없으면 그 사실 자체가 기록이고, 과제의 해당 항목에 그렇게 쓴다.
