# Task E-4: API Contract 설계 (스키마 우선, 에러 체계, 멱등성 기초)

(Grit's Why): E-3에서 못 박은 요구사항을 이제 기계와 동료가 함께 읽는 계약으로 만듭니다. 명세가 곧 계약입니다.

### 수행 내용

1. E-3의 기능을 스키마 우선(OpenAPI 또는 Protobuf)으로 API 계약으로 작성하세요. 요청과 응답 스키마, 필수와 선택 필드, 제약 조건을 명시합니다.
2. 에러 코드 체계를 세우세요. 4xx(클라이언트 잘못)와 5xx(서버 잘못)를 구분하고, 비즈니스 에러(예: 재고 없음)와 시스템 에러(예: DB 타임아웃)를 분리하세요. 각 에러의 의미와 클라이언트가 어떻게 대응해야 하는지 적습니다.
3. 멱등성 기초. 재시도가 안전해야 하는 엔드포인트 1개를 골라 Idempotency-Key를 설계하세요. 키를 어떻게 만들고, 어디에 저장하며, 중복 요청이 오면 어떤 응답을 돌려줄지 정합니다. (분산 환경 멱등성은 Station 2-4에서 심화합니다.)

### 제출물

- [ ] OpenAPI 또는 Protobuf 계약 파일을 GitHub에.
- [ ] 에러 코드 체계표(비즈니스 에러와 시스템 에러 분리).
- [ ] 멱등성 설계 메모(Idempotency-Key의 생성, 저장, 중복 응답 흐름). (최소 300자)
