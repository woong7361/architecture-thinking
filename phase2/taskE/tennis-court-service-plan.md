# 빈자리 알림 기능 요구사항 명세서

관련 과제: [Task E-3 — 제출물 2](https://github.com/woong7361/architecture-thinking/blob/main/phase2/taskE/assignments/taskE-3.md)

## 목적과 범위

사용자가 지정한 코트·날짜·시간대에 빈자리가 생기면 알려, 외부 예약 사이트에서 예약을 시도할 수 있게 한다. 범위는 알림 신청·조회·해제, 예약 상태 확인, 알림 발송, 만료까지다. 예약과 취소는 외부 사이트에서 이뤄지며, 이 서비스는 예약 성공 여부를 알지 못한다.

- 신청 단위는 코트 하나, 날짜 하나, 시간대 하나다.
- 신청은 감시 중으로 시작해 알림 완료·해제·만료 중 하나로 끝난다. 끝난 신청은 되살아나지 않는다.
- 만료 시각은 이용 시작 시각이다. 더 이른 예약 마감 시각이 확인되면 그 시각을 쓴다.

## 기능 요구사항


| 번호   | 기능        | 요구사항                                                                                     |
| ---- | --------- | ---------------------------------------------------------------------------------------- |
| FR-1 | 알림 신청     | 지원하는 코트·시간대이고 만료 전이면 신청을 저장하고 감시 중으로 돌려준다. 같은 사용자가 같은 조건으로 다시 신청하면 기존 신청을 돌려준다.          |
| FR-2 | 신청 조회와 해제 | 자신의 신청 조건, 상태, 마지막 확인 시각, 확인 지연 여부, 발송 결과를 볼 수 있다. 해제하면 확인과 발송을 멈춘다. 남의 신청은 조회·해제할 수 없다. |
| FR-3 | 예약 상태 확인  | 코트·날짜 단위로 20초마다 확인한다. 확인에 실패하면 빈자리 없음으로 다루지 않고 마지막 성공 결과를 유지한다.                          |
| FR-4 | 알림 발송     | 빈자리를 확인하면 발송 대기에 기록하고, 발송은 별도 작업이 맡는다. 신청 하나에 알림은 한 건만 보내며, 발송되면 신청은 알림 완료가 되어 확인을 멈춘다.  |
| FR-5 | 만료        | 만료 시각이 되면 확인과 발송을 멈춘다.                                                                   |
| FR-6 | 알림 메시지    | 알림 한 건에 아래 네 가지를 담는다. 발송 수단은 아직 정하지 않았다.                                                 |


FR-2의 확인 지연은 마지막 성공 확인이 확인 간격의 세 배를 넘긴 상태를 뜻한다. 한 주기만 걸러도 지연으로 보면 작업이 조금 밀린 것까지 지연으로 표시되어 신호가 무뎌지고, 세 주기를 연달아 거르면 한 번의 실패가 아니라 확인 경로가 끊긴 것으로 볼 수 있다.

## 알림 메시지

FR-6이 정한 알림 한 건의 내용이다.

- 코트·날짜·시간대
- 빈자리를 확인한 시각
- 외부 예약 사이트 링크
- 예약을 보장하지 않는다는 안내

발송 수단은 정하지 않았다. 웹 푸시와 앱 푸시는 위 내용을 그대로 실어 보내지만, 알림톡이나 문자는 승인받은 템플릿과 변수 목록이 따로 필요하다. 어느 채널을 먼저 붙일지 정해야 그 부분을 채울 수 있다.

## 비기능 요구사항


| 번호    | 기준    | 초기값                                | 근거                                                                           |
| ----- | ----- | ---------------------------------- | ---------------------------------------------------------------------------- |
| NFR-1 | 처리 규모 | 가입자 200명, 감시 중 신청 500건, 피크 초당 200건 | 가입자는 오픈채팅방 1000명 × 가입 전환 20%. 신청은 1인당 2~3건. 피크는 예약 오픈 시각에 전원이 1초마다 갱신한다고 본다. |
| NFR-2 | 응답시간  | 피크에서 95%를 1초 이내                    | 갱신 간격보다 길면 요청이 쌓인다.                                                          |
| NFR-3 | 확인 간격 | 코트·날짜마다 20초, 외부 조회는 한 번            | 예약처 허용량을 몰라 보수적으로 시작한다.                                                      |
| NFR-4 | 발송 시점 | 발견 즉시 발송                           | 빈자리는 금방 사라진다.                                                                |


## 실패 흐름


| 번호   | 상황                  | 계약                                                                                                                                                        |
| ---- | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| EF-1 | 예약 상태를 가져오지 못함      | 빈자리 없음이 아니라 일시적인 확인 실패로 표시하고, 잠시 후 다시 확인해 달라고 안내한다. 응답은 왔지만 읽지 못한 경우도 실패다. 신청자에게 따로 연락하지 않고 신청 조회에서 확인 지연으로 보여준다.                                         |
| EF-2 | 여러 사람이 같은 때에 갱신을 누름 | 한 요청만 예약처를 조회하고, 나머지는 기다렸다가 저장된 같은 결과를 받는다. 그 조회가 실패하면 모두 확인 실패를 받는다.                                                                                     |
| EF-3 | 발송이 실패하거나 결과를 모름    | 최대 3번 다시 보낸다. 결과를 모르는 경우도 다시 보내 누락 대신 중복을 감수한다. 모두 실패하면 DLQ로 옮기고 다시 보내지 않는다.                                                                              |
| EF-4 | 발송이 밀려 정보가 오래됨      | 같은 코트·날짜에 더 최신 확인 결과가 나오면 이전 결과로 만든 알림은 보내지 않고, 최신 결과로 다시 만들어 보낸다. 최신 결과에 빈자리가 없으면 보내지 않고 신청은 감시 중으로 남는다. 최신 결과는 저장된 확인 결과를 쓰며, 발송 직전에 예약처를 다시 조회하지는 않는다. |
| EF-5 | 같은 자리를 반복해서 발견      | 알림은 한 건만 보낸다. 이후 상태 변화는 앱과 웹에서 보여준다.                                                                                                                      |
| EF-6 | 알림이 만료된 뒤에 도착함      | 단말이 꺼져 있다가 나중에 켜지면 알림은 그때 도착한다. 만료 시각이 지난 뒤 도착한 알림은 띄우지 않는다. 그 시각이 지나면 이용 자체가 시작돼 예약을 시도할 수 없기 때문이다. 알림에 만료 시각을 함께 실어 받는 쪽이 판단한다.                    |


## 검증 시나리오

- V-1: 같은 조건으로 동시에 두 번 신청해도 신청은 하나다.
- V-2: 빈자리가 계속되거나 찼다가 다시 비어도 알림은 한 건이다.
- V-3: 확인 실패만으로는 알림이 생기지 않는다.
- V-4: 같은 코트·날짜에 갱신 200건이 동시에 와도 외부 조회는 한 번이고, 모두 같은 결과를 받는다.
- V-5: 발송이 밀린 사이 새 확인 결과가 나오면, 알림은 이전 결과가 아니라 최신 결과의 내용으로 나간다.
- V-6: 그 최신 결과에 빈자리가 없으면 알림은 나가지 않고 신청은 감시 중으로 남는다.
- V-7: 발송 실패 시 최대 3번 재시도하고, 모두 실패하면 DLQ로 옮겨진다.
- V-8: 해제·만료 뒤에는 새 발송이 시작되지 않는다.
