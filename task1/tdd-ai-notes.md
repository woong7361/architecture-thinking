## 관통 서사 (한 문장)

> AI는 통과만 하면 가짜로라도 짠다(가짜로 구현). 그래서 테스트는 빨강을 본 것만
> 믿을 수 있고(빨강 먼저), 결국 AI에게 줄 것은 프롬프트가 아니라 실행 가능한 명세다.

## 0. 개념 정리: 게이트 ≠ TDD, 결정론은 권한 경계에서 온다

핵심 반문: "AI에게 테스트를 게이트로 주는 건 TDD가 아니고, AI가 그 게이트를
고칠 수 있으면 결정론적이지도 않은 것 아닌가?" → 대체로 맞다. 아래로 정리.

### (a) TDD(과정) vs 결정론적 게이트(역할)는 다른 것

- **TDD** = 과정. red→green→refactor로 **설계를 발견해가는 규율**. 코드 작성자를 위한 것.
- **결정론적 게이트** = 역할. 완성된 테스트가 코드를 **판정하는 검증 장치**.
- 벡의 테스트는 둘을 동시에 함. AI에게 게이트를 주면 **검증 절반만** 쓰는 것.
- 결론: "AI에게 게이트를 준다" = 순수 TDD 아님. **ATDD/명세 우선**에 가깝다.
  단, 사람이 테스트(red)를 쥐고 AI가 green을 반복하면 **TDD 리듬은 재구성 가능**.
  이때 설계 발견의 이득은 **테스트를 쓰는 사람**에게로 이동하고, AI는 구현자가 됨.

### (b) 비대칭: 테스트는 닻, 코드가 휜다

- "테스트를 고쳐가며 코드를 짠다"는 부정확. 테스트를 **고치지 않고 늘린다.**
- 리팩터링은 테스트를 **초록으로 유지한 채** 구조만 바꾸는 것.
- 테스트 변경 = "통과시키기"가 아니라 **명세를 바꾸는 별개의, 보이는 결정**.
- 정확한 표현: "테스트를 늘려가며, 코드가 거기 맞춰 자란다."

### (c) 결정론은 테스트의 속성이 아니라 권한 경계의 속성

- 결정론 정의: 고정된 테스트 + 고정된 코드 → 재현 가능한 pass/fail. **한 판정 순간의 성질.**
- 위험: 코드를 짜는 AI가 테스트도 고칠 수 있으면, 코드 대신 **테스트를 약화시켜
  초록**을 만든다(리워드 해킹). 이 순간 게이트는 판정 능력을 잃음 = 결정론 붕괴.
- 해결(경계가 게이트의 본체):
  1. 사람이 게이트를 소유, AI는 프로덕션 코드만 건드림.
  2. AI가 테스트를 바꿔야 하면 "통과시키기"에 섞지 말고 **사람이 리뷰하는 별개 diff**로.
  3. 결함 주입(mutation)으로 게이트가 아직 이빨이 있는지 주기 검증.
  4. 같은 세션 AI의 자기평가를 판정 근거로 삼지 않음. (task1/CLAUDE.md 원칙과 일치)

## 1. 개념 → AI 대입 표

| 개념 | 인간 맥락 | AI 대입 | 출처 |
|---|---|---|---|
| **빨강 먼저** | 테스트가 뭔가 검증하는지 확인 | 게이트의 뿌리. AI가 테스트까지 짜면 처음부터 초록인 "봉인된 테스트" → 아무것도 못 잡음. 인간이 빨강을 본 테스트만 AI 코드를 판정할 자격 | 3부(빨간 막대) |
| **가짜로 구현 / 삼각측량** | 작은 보폭 일반화 | AI 오버피팅·리워드 해킹 방어. 케이스 1개면 AI가 `if x==3 return 5` 특수해로 초록. 데이터 포인트 2개↑로 일반화 강제 | 1·3부 |
| **단언 우선** | 결과부터 거꾸로 | AI에게 목표(target)를 먼저 고정. "잘 짜줘"(모호) 대신 통과할 단언을 먼저 = 프롬프트의 결정론적 버전 | 3부(빨간 막대) |
| **중복이 설계를 이끈다** | 리팩터링이 구조 창발 | AI 리팩터링 안전망. 초록 유지 조건에서 AI가 구조를 바꿔도 회귀 없음. 테스트 없으면 AI 리팩터링은 도박 | 1부 |
| **테스트도 코드다** | 테스트도 관리 대상 | 신뢰의 원천 오염 방지. AI가 테스트도 생성 → AI가 짠 테스트를 인간이 리뷰하는 게 최후 보루 | 3부 |
| **테스트 어려움 = 설계 신호** | 강결합 피드백 | AI 코드 품질의 프록시 지표. AI 코드가 테스트 붙이기 어렵다 = 설계 냄새. 자연어로 못 주는 "좋은 설계"의 객관 신호 | 3부 |
| **테스트 목록(To-Do)** | 한 번에 하나 | AI 스코프·컨텍스트 관리. AI는 한 방에 과잉 구현. 목록으로 쪼개 "하나씩 통과" → diff 작아지고 리뷰 가능 | 3부 |
| **깨진 테스트로 끝내기** | 다음 날 재진입 표식 | 세션 관리 직결. 세션이 끊겨도 실패 테스트 1개가 "다음 세션 시작점"을 결정론적으로 표시. 인간 기억 대신 테스트가 컨텍스트 보존 | 3부 |
| **명백한 데이터** | 테스트가 문서 | AI가 읽는 실행가능 문서. AI는 코드베이스 전체를 못 봄. 관계가 드러나는 데이터면 AI가 의도 파악 | 3부 |

## 2. AI에 특히 잘 붙는 개념 (확장)

- **실행 가능한 명세 (Executable Specification)** ★
  - 근거: 인수테스트/Gherkin = "사람과 기계 모두 읽는 명세".
  - AI 대입: 자연어 프롬프트는 모호+비결정적. 테스트는 기계가 판정하는 정밀 계약.
    AI에게 "무엇을"을 전달하는 가장 오차 없는 언어. 스프린트의 Gherkin = AI 계약서.

- **결함 주입으로 게이트 검증 (Mutation)** ★ (task1/CLAUDE.md 결정론적 게이트 원칙과 직결)
  - 근거: "테스트가 통과해도 이 변경을 잡는지 확인"(빨강 확인).
  - AI 대입: AI 코드에 일부러 결함 하나 심어 Red 되는지 확인. Red 안 되면
    그 테스트는 AI를 통제할 힘이 없음.

- **자기 검증(Self-validating) = AI 루프의 종료 조건**
  - 근거: FIRST의 S. Pass/Fail로 명확히 갈림.
  - AI 대입: 테스트가 스스로 판정 → AI가 인간 개입 없이 반복(생성→판정→수정).
    자율 에이전트 루프의 종결자. (AGENTS.md Level 4~5 목표와 연결)

- **아주 작은 단계 = AI에게 주는 작은 diff**
  - 근거: baby steps, "생각보다 훨씬 작은 보폭".
  - AI 대입: 큰 변경은 AI가 헛나가고 리뷰 불가. 작은 단계 = 검증 가능한 최소 diff 단위.

## 3. 2·3부 원전 개념 메모 (재료 보관용)

- **자기 참조 부트스트랩** (2부): xUnit을 그 xUnit으로 테스트로 만든다. 맨손 assert
  하나로 도구를 끌어올림 → "환경이 갖춰져야 테스트한다"는 전제 붕괴.
- **setUp/tearDown 발명** (2부): 당연히 쓰던 기능이 격리 필요에서 발견됨.
- **실패 수집** (2부): 첫 실패에서 안 멈추고 모아서 리포트. 실패 처리도 설계 대상.
- **자식 테스트** (3부): 지금 테스트가 너무 크면 더 작은 테스트로 쪼개 통과 후 복귀.
- **기어 바꾸기** (3부): 자신 있으면 명백한 구현, 막히면 가짜로 구현/삼각측량.
  보폭은 고정이 아니라 판단.

## 4. 에세이용 추천 3종 (AI 관점)

역할이 겹치지 않게: **게이트 / 명세 / 안전망**

1. 빨강 먼저 + 결함 주입 — "AI 코드를 왜 못 믿나, 뭘로 믿나"의 뿌리
2. 가짜로 구현 / 삼각측량 — AI 리워드 해킹을 벡이 예언한 셈
3. 실행 가능한 명세 (또는 깨진 테스트로 끝내기=세션 관리)

강추 조합: **1 + 2 + 3** → "각성 서사"로 이어져 "이미 아는 얘기" 방어에 강함.
