# 회사 규모별/도메인별 백엔드 채용 요구 역량·언어 차이

## 핵심 요약

- 표본 내 32개 공고에서는 Java, Spring Boot, MySQL, REST API가 백엔드 기본 역량의 공통 언어로 반복됐다.
- 회사 규모가 작을수록 “End-to-End”, “주도”, “문제 정의”, “작은 팀”처럼 역할 범위와 책임을 넓게 요구하는 표현이 두드러졌다.
- SaaS·스타트업 계열에서는 AWS, Docker, Kubernetes, CI/CD처럼 개발자가 배포·운영 환경까지 이해하길 기대하는 표현이 자주 관찰됐다.
- 금융·정산·결제 문맥에서는 기술 스택보다 거래 흐름, 데이터 정합성, 트랜잭션, 정책 변화 대응을 시스템으로 옮기는 역량이 중요하게 읽힌다.
- AI/LLM 표현은 연구 역량보다는 제품 기능 연동, 개발 워크플로우 개선, 결과물 검증 역량으로 해석하는 편이 적절하다.

## 표면 기술 요구와 실제 기대 역량

| 표면 표현 | 실제 기대 역량 |
| --- | --- |
| Java, Spring Boot, Spring Framework | 서버 애플리케이션을 구조화하고, API·도메인·DB 계층을 운영 가능한 형태로 구현하는 기본기 |
| MySQL, RDBMS, PostgreSQL, MongoDB | 단순 저장소 사용이 아니라 데이터 모델링, 정합성 유지, 조회 패턴과 성능을 고려한 설계 |
| REST API, RESTful API | 프론트엔드·외부 시스템과 맞물리는 계약을 안정적으로 정의하고 유지하는 능력 |
| AWS, Docker, Kubernetes, CI/CD | 코드 작성 이후의 배포, 운영 환경, 클라우드 자원, 자동화 흐름을 이해하는 능력 |
| Redis, Kafka, 메시지 큐, 비동기 처리 | 실시간 이벤트, 피크 트래픽, 지연 처리, 장애 전파를 고려한 운영 설계 |
| 장애 대응, 모니터링, 트러블슈팅 | 문제가 생겼을 때 임시 조치에 그치지 않고 원인 분석, 지표 확인, 재발 방지 구조 개선까지 이어가는 역량 |
| 결제, 정산, 여신, 정책, 관제 | 업무 흐름과 규칙을 데이터 모델, 상태 전이, 트랜잭션 경계, API 계약으로 옮기는 능력 |
| AI 도구, LLM API, AI 에이전트 | AI 결과물을 제품 기능이나 개발 워크플로우에 연결하고, 산출물을 비판적으로 검증하는 능력 |
