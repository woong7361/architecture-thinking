# Task B-0: 이번 Station의 책 (마인드셋 1권 + 기술 2권 + 팀그릿)

(Grit's Why): 객체지향은 '클래스 쓰는 법'이 아니라 '변경 비용을 설계로 낮추는 법'입니다. 이번 Sprint 책은 그 사고를 잡습니다.

### 읽기 범위 (3축: 기술 / 마인드셋 / 팀그릿)

- [기술] 오브젝트(조영호): 1~2장(객체지향 설계의 본질, 역할·책임·협력)은 정독, 의존성과 유연한 설계 장은 B-4 전에 읽어 주세요.
- [기술] 리팩토링 2판(마틴 파울러): 1장(예시로 보는 리팩토링)을 손으로 따라가며 '작은 단계 + 테스트 그린 유지'의 리듬을 익히고, 코드 스멜 카탈로그(3장)는 B-5의 참조표로 쓰세요.
- [마인드셋] 소프트웨어 장인(산드로 만쿠소): 코더와 장인의 차이, 책임감을 다루는 대목을 객체 설계의 태도와 연결지어 읽어 주세요.
- [팀그릿] 서재 전자책: ai-native-development-guide Ch7~8(AI 시대 클린 아키텍처/경계), claude-code-one-person-team Ch6(품질 게이트), ai-backend-guide Ch10. ai-native Ch7~8은 B-1/B-4 사고에, one-person-team Ch6 + ai-backend Ch10은 B-6 파이프라인에 연결해 읽어 주세요.

### 제출물

- [ ]  [오브젝트] 가장 충격적이었던 구절/개념 세 가지와, 각각 왜 본인의 기존 설계 방식을 흔들었는지. (최소 400자)
- [ ]  [리팩토링] '작은 단계로 옮기며 테스트로 매번 확인한다'는 리듬이 1-1의 테스트와 어떻게 이어지는지 한 문단. (최소 200자)
- [ ]  [소프트웨어 장인] 코더와 장인의 차이 중 본인에게 가장 뼈아픈 지점 하나와, 이번 Station에서 어떻게 좁힐지. (최소 300자)
